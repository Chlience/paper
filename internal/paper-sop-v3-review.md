# Paper 阅读 SOP 审查与 v3 修订

Date: 2026-09-05
Baseline: e56384709b8870333eadf871c309121f1ef421e5
Scope: 单篇材料的阅读、分析、归档契约及其执行与验证；保留现有论文、作者数据和研究主线。

## 审查结论

v2.1 已经建立了重要基础：分析与写入分开，要求完整方法、直接证据和最窄结论，限制作者与跨论文维护的扩张，并明确人工审查不可由自动检查替代。主要问题出在执行重心：阅读质量的一部分被转换成标题位置、关键词和段落配额，证据是否足以区分解释却主要依赖执行者自行补足。重复规范和与之逐句对应的测试又提高了修订这些规则的成本。

v3 将工作流围绕一个可复查判断组织：问题与版本决定所需主张，主张决定阅读路径，方法重建明确研究对象，判别性证据决定可接受结论，归档只保存这条链中有用的内容。保留方法理解的深度要求，同时撤销没有独立质量收益的固定产物。

这是基于仓库文档、验证器、测试和笔记样本的工作流审查。本次没有重新读取全部原始论文，不对 115 篇笔记逐篇科学正确性作结论；笔记长度与重复结构也不能直接证明阅读耗时或内容质量下降。

## 主要问题与判断依据

### 1. 阅读问题缺少稳定的约束作用

旧流程先进行材料分类、来源与作者检查，完成定义包含大量归档项；阅读目标只在复杂材料中作为可选章节。它也规定局部分析可以缩小范围，但没有明确要求将每条决定答案的主张映射到所需证据。执行者容易先解释论文目录，再判断这些解释是否回答用户问题。

修订将“用户要判断什么、答案依赖什么证据”放在入口，并在成文前逐项核对。主张地图是临时工作记录，避免再增加一个固定公开表格。用户未指定问题时使用贡献、机制、证据、边界的整篇默认范围；关键材料缺失时允许明确的有限答案。

### 2. 固定思考路径促使每篇材料产生推测性叙事

31 篇 v2.1 笔记都采用相同的“作者可能的思考路径”标题。该节要求本地重构，即使明确标注推断，也会让每篇论文都有一段无法直接观察的创意形成过程。SMELT 的该节实际复述预算匹配、架构选择、缩放与探针分析顺序；这些信息适合进入设计理由或方法链条。

这项统计支持“模板稳定地产生了该章节”，没有证明其中所有推断错误。v3 保留来源明确披露的设计动机和有用的本地设计解释，取消单独推测作者心理过程的要求。这样可以保留可检验的理由，并减小背景、思路和方法之间的重复。

### 3. 方法总览的目标正确，固定第 5 节缺少必要性

旧规则的两层复述标准有实际价值：复杂方法需要先识别角色、更新对象与数据流，再解释关键操作。EcoSpec 笔记对“专家标识集合”和“物理权重缓存”的区分，是这种解释应当保护的对象边界。

问题是校验把该目标绑定到第 5 节、连续编号、两个精确标题和预设关键词。保留完整内容、把总览移到第 1 节会产生硬错误；把总览换成关键词堆砌可以通过。单阶段必须内联、多阶段必须提升同级标题，也不能独立保证理解质量。

v3 保留一个可识别的总览入口和两层复述验收，允许编号、位置和详解层级按解释需要安排。总览没有辅助贡献时可以只解释首要贡献；人工自审检查对象、接口、信号和条件，自动检查只判断入口存在且有可见内容。

### 4. 直接证据的最低数据要求低于结论要求

旧 v2.1 校验强制 `证据定位` 与 `支持的最窄结论`，却允许结果完全没有观察值；模板 fixture 原本用“结果：有效”，删去这一行仍然零错误、零提示。定位与一句结论之间缺少可检查的中间对象。

v3 增加 `观察` 和 `判别性与局限`，形成四个证据字段。观察可以是数值、关系、证明或文档行为，不要求每篇都产生性能表；必须交代谁报告、采用什么设置、比较什么，以及为何支持后面的结论。字段存在仍不能证明内容正确，科学自审必须核对原始材料。

### 5. 机制复述与因果识别需要分开验收

旧文档已经要求可比性、最窄边界、直接证据和局限，但“方法如何执行”与“收益为什么出现”的验证路径没有充分拆开。能复述一个算法、看到一个消融变好、观察到一个内部探针变化，分别提供不同证据；把它们串成流畅叙事仍可能越过证据支持范围。

v3 明确区分设计事实、观测或证明结果、作者解释与本地判断。判别性检查要求说明对照固定和改变了什么，最相关的替代解释是否仍成立。系统的 FLOPs 与实际时间、理论的存在性与可学习性、模型报告的联合配置与结构效应分别处理。相应问题写入模块细则，并提供人工正反例。

### 6. 固定检索次数无法表达证据充分性

旧规则用“同一主张连续两个来源没有改变结论”停止扩展，审稿定位最多增加一次标题或 ID 匹配。两份来源可能转述同一结果，也可能都没有涉及关键混杂因素；一次查询失败受索引、标题和访问条件影响。反过来，证据已经完整时额外凑查询也没有收益。

v3 按尚未解决的问题决定是否继续。停止需要答案、关键机制、直接证据与边界闭合；无法闭合时记录阻塞或有限结论。没有公开代码、没有消融和存在未披露项，并不一律触发复现或全网检索；只处理改变当前判断的缺口。

### 7. 审稿状态混淆了“未查”“未找到”和“不可访问”

旧枚举缺少 `not-checked` 与 `unavailable`，`not-found` 仍要求 high / medium / low 匹配置信度。没有候选时，身份匹配置信度没有对应对象。正文还要求正式评审存在时归纳 reviewer 共识，而默认优先读 decision 或 meta-review，存在把决定文件解释成全面共识的风险。

v3 将观察状态和身份匹配分开。未核验、未匹配、不可访问和不适用都使用 `match-confidence=not-applicable`；检索或访问失败保留范围记录。已读元数据、出版记录或评论需要对应 URL；正式评审章必须说明具体已读材料。只读 decision 可以如实记录其内容，不需虚构质疑、回应或 reviewer 共识。

### 8. 阅读缺口没有稳定进入来源快照

旧 Source 有所读版本与访问日期，但不能区分“读取了整篇”“只读摘要”“附录无法获取”。正文中的“未披露”容易与尚未读取混合，特别是关键参数在附录或版本更新中出现时。

v3 用单个短文本字段 `Reading scope` 保存已读范围和影响判断的缺口，不增加多级阅读状态机。SOP 明确未读应继续读、不可访问应说明限制、原材料未披露才记录披露缺口。用户要求保存不完整材料时允许有限归档，并要求结论相应收缩。

### 9. 主要启发的迁移要求筛掉了有价值的局部认识

旧启发构建需要九步推理、区分性证据、机制、迁移预测，以及二至三个自然段。这套要求适合构建跨场景设计假设，但一个反例缩小适用域、一个定理澄清存在性边界，也可能形成稳定认识，未必需要另一目标任务。固定迁移还可能诱发只有表面对应关系的类比。

v3 用“有来源的认识变化、触发证据、新判断、成立边界”决定是否保留。外推仍需具体目标、保留的抽象关系和可证伪预测；缺少判别性证据的因果解释仍是待验证假设。数量和自然段配额撤销，单段有证据的局部认识可以成立。

### 10. 可见性漏洞使空内容满足硬约束

旧章节存在性检查直接读取原始 Markdown，`局限` 仅保留 HTML 注释仍能通过。方法部分虽然剔除了注释并解析标题，其它核心部分没有同等处理，导致同一个“实质内容”要求的执行不一致。

v3 校验先排除注释与代码示例，再检查真正的顶层核心章节、证据字段和总览。重复核心章节、仅标题、仅注释、未填写占位和空字段不能满足要求。科学内容仍可错误，验证器不宣称具备事实判断能力。

### 11. 文档重复与文字匹配测试增加契约漂移

旧方法总览、启发构建与更新时间规则同时出现在主 SOP、AGENTS、模板和维护 SOP；语料测试要求多份文档逐项包含相同短语。更新时间还直接冲突：主 SOP 的来源与版本段要求纯维护保留时间，本地审阅段及维护 SOP 又要求排版和链接修订更新时间。

v3 为每类规则指定规范来源：主 SOP 负责阅读与科学判断，模板提供骨架，模块文档给出条件问题，维护 SOP 管仓库操作，AGENTS 保存边界与路由。取消多份文件逐句复述科学规则的测试，改为验证公开模板可填写成有效笔记、入口版本一致以及实际边界行为。更新时间统一为实质内容变化；审阅历史单独保存。

时间校验还把同一分钟的两个归档视为冲突，实际排序器 `comparePapersForReviewFilter` 已用 slug 处理相同时间。v3 允许真实时间相同，避免为了通过检查人为错开分钟；旧版本之间仍保留原兼容行为。

### 12. 迁移需要限制新增兼容债务

直接把全部旧笔记按新规则校验，会推动一次与当前阅读任务无关的批量改写；继续在 v2.1 上叠时间条件，又会让同版本含义不断漂移。现有 approved 记录还承载用户历史确认，不能由工作流升级重新解释。

v3 使用显式版本分支。保留旧校验与现有数据，冻结 31 篇 v2.1 的身份和更新时间上限；新材料声明旧版本会失败，既有 v2.1 更新时间改变则要求迁移并移出名单。迁移保留原始事实、用户判断和审阅历史。旧兼容实现的复杂度仍存在，但其覆盖范围固定，新增笔记使用清晰的新契约。

## 方案取舍

保留七个核心信息区域、索引与标签、来源追溯、图片归因和本地审阅历史。作者与跨论文关系可以简短或合并表达，并置于科学分析之后。取消这两类信息区域会引入站点与已有档案语义变化，本次缺少必须这样做的证据。

采用 v3 是因为硬字段、审稿枚举和叙事约束发生实质变化；改一个标题或缩短 SOP 无法交付这些行为。新增实现隔离在 `scripts/content/paper-reading-contract.mjs`，复用既有 Markdown 解析依赖；没有引入外部服务、自动打分器或复现基础设施。

本次不改研究主线的建立规则、作者身份 schema、全库论文内容、Git 历史或用户审阅状态。SOP 文本的大幅替换和兼容分支新增均可由本地提交回退；没有执行论文删除、目录清理或历史改写。

## 验收与剩余边界

验收覆盖新契约正反例、公开模板实例化、旧版行为、v2.1 冻结名单与更新时间、审稿状态、渲染可见性、索引标签及全库零硬错误。两份 v3 fixture 分别覆盖系统/文档行为和理论等价性推导，使用明确标注的虚构规范；它们证明契约可表达两类材料，不构成真实论文阅读质量的效果试验。

科学自审逐项检查了修订与问题的对应、机制复述标准、观察到结论的连接、迁移边界与有限交付路径。代码只验证结构，不核验数字真伪、实验可比性、因果解释或新颖性。实际阅读时间、错误率和用户重读成本尚无受控测量；后续在真实阅读中观察这些结果，不能由行数下降推断提升比例。

实际验证结果：

- `rtk npm run check:source` 通过：139 项单元测试、15 项语料测试；115 篇论文与 412 个作者 profile 的工作流检查、3 条主线检查、元数据与公式检查零硬错误。原有 advisory 保留。
- 新增 16 项 v3 单元测试，覆盖系统与理论示例、自由章节、空内容与占位、四项证据字段、阅读范围、简短启发、审稿状态、版本兼容、更新时间迁移、真实分钟并列与图片来源；公开模板填写测试进入语料检查。
- `rtk git diff --check` 通过。论文、主线、作者与标签数据、图片目录没有差异。
- 主 SOP 从 344 行重组为 167 行，模板从 180 行缩减为 95 行；这仅说明文本规模变化。

未执行 production build、浏览器检查、部署或真实论文阅读效果试验。此次渲染验证覆盖 v3 来源状态、阅读范围与证据正文的可见性；生产构建和部署仍由 GitHub Actions 负责，推送需要用户明确要求。
