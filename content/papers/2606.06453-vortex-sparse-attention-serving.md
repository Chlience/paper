## 一句话结论

Vortex 用 `vFlow` 描述 page summary、逐 token 动态路由与 selected attention，用 `vTensor` 把这些逻辑算子 lowering 到 paged / ragged layouts，再复用或补充 SGLang 的 GQA / MLA decode backend，使 sparse-attention selector、top-k 和真实 KV layout 能在同一端到端 serving 路径中实现和评测；Qwen3 与 MiniMax-M2.7 实验支持它降低动态 sparse attention 的实现成本并获得实际 decode 收益，AI-agent 实验支持框架可以承载自动候选生成与搜索，GLM-4.7-Flash 的最高 $4.7\times$ 同时混入 dense Triton 与 sparse `cuda_mla` backend 差异，且当前范围不含 sparse prefill、训练 backward 和真实多轮 agent 生产流量。

## 论文脉络

### 1. 研究问题、背景和价值

训练或推理阶段提出一个 sparse-attention rule 往往只需要几行数学：为历史 block 构造 summary，用当前 query 打分，取 top-k blocks，再对选中的 KV 做 attention。真实 LLM serving 增加了另一组约束：不同请求的 KV 分散在物理 pages 中，batch 内序列长度不同，prefix cache 会共享 pages，decode batch 持续变化，selector 自身还会引入 reduction、top-k、gather 和 metadata planning。

因此，算法级 FLOPs reduction 能否转成 end-to-end throughput，取决于 selector 与 serving runtime 是否共享同一套 layout 和 memory manager。Vortex 试图缩短的路径是：

$$
\text{算法表达}
\rightarrow
\text{paged selector/indexer}
\rightarrow
\text{sparse block table}
\rightarrow
\text{optimized decode attention}
\rightarrow
\text{end-to-end evaluation}.
$$

这一问题对 agentic workload 有价值，因为长 reasoning、RL rollout 和多轮 agent 会把 decode 长度与 KV movement 放大。Vortex 当前仍只优化 attention-based decode path，不能覆盖工具等待、request scheduling、reward execution 或 training update。

- 证据定位：论文 Section 1，Figure 2；作者将 paged KV 的非连续 layout、dynamic sparsity construction、programmability 和 serving compatibility 列为三个主要缺口。

### 2. 已有解决方案与不足

FlashInfer、FlexAttention 等系统可以在 sparse indices 或 mask 已知后执行高效 attention。动态 sparse attention 还需要根据当前 query 生成这些 indices；论文认为这段 indexer path 有时比 selected attention 本身更贵。SGLang、vLLM 和 LMDeploy 提供 paged KV、continuous batching 与 prefix caching，但加入新 selector 往往需要重写 cache summary、paged GeMM、reduction、top-k 和 backend plumbing。

论文用 Double Sparse 的 SGLang 实现约 2000 行，以及 Quest 原实现评测 Llama-3.1-8B / AMC23 时比 SGLang full attention 慢 $44.4\times$，说明“有 sparse kernel”仍可能留下巨大的 integration overhead。这些数字来自作者自身比较，适合说明系统动机，不能当作所有既有 sparse-attention implementation 的普遍性能。

- 证据定位：论文 Section 1，第 2-3 项 gap；PDF page 2 对 Double Sparse 代码量与 Quest `44.4x` slowdown 的描述；Section 2 对 FlashInfer、FlexAttention、LServe 和 SparseServe 的定位。

### 3. 作者可能的思考路径

1. 把 sparse attention 拆成 query-independent cache construction 和 query-dependent routing，使跨 decode steps 可复用的 summary 显式化。
2. 给算法作者一个 batch-size-one 的逻辑视图，隐藏真实 batch、page table 与 ragged layout。
3. 用 layout-aware `vTensor` 保留物理信息，让逻辑算子能被 lowering 到 paged execution。
4. 把 selector 生成的 sparse block table 交给现有 optimized attention backend，避免每个算法重新实现 selected attention。
5. 将编译、运行和质量/吞吐评测包装成稳定接口，使 coding agent 可以提交候选并读取结果。

这条路径将系统贡献集中在“动态 sparsity construction + serving execution”之间的接口，而具体 block top-k、Quest、H2O 或 agent-generated flow 都是该接口上的程序实例。

### 4. 核心假设或切入点

Vortex 依赖四个条件：

- **表达条件**：常见 dynamic sparse attention 可以分解成 cache update、indexer operators 和 selected attention。
- **layout 条件**：对每条 sequence 独立执行的 tensor semantics 可以在 batch、paged 和 ragged layouts 间传播。
- **执行条件**：workload planning、fusion 与 approximate top-k 能把 abstraction overhead 控制在 sparse attention 节省量之下。
- **评测条件**：端到端 serving benchmark 能同时约束质量与吞吐，避免 selector 只在离线 tensor microbenchmark 中成立。

当前实现禁止 operator 改变 batch dimension，这与 serving 中 sequence-wise independent computation 相符；需要跨 sequence interaction 的算法会超出抽象范围。

- 证据定位：论文 Sections 3-5、Appendix B；项目 `AI/AGENTS.md` 与 `vortex_torch/flow/algorithms.py` 给出 flow contract 和可用 operator 范围。

### 5. 方法 / 系统 / 理论框架

#### 5.1 `vFlow`：把 sparse attention 拆成 cache 与 indexer 两阶段

一个 `vFlow` 主要声明三件事：

| 接口 | 调用时机 | 作用 |
| --- | --- | --- |
| `create_cache` | engine 初始化 | 声明每个 page 需要保存的辅助状态，例如 centroid、max/min 或累计 attention mass |
| `forward_cache` | page 完成或 cache 更新时 | 从 K/V 构造 query-independent summary |
| `forward_indexer` | 每个 decode step | 用当前 query 和 cached summaries 打分，并输出 selected pages |

以 block top-k 为例，第 $j$ 个 block 的 key centroid 为：

$$
\widetilde{\mathbf k}_j=\frac{1}{b}\sum_{s\in B_j}\mathbf k_s,
$$

当前 query 对 block 打分并选择：

$$
z_j=\mathbf q^\top\widetilde{\mathbf k}_j,
\qquad
\mathcal B=\operatorname{TopK}_j(z_j,k),
$$

随后 attention backend 只读取 $\mathcal B$ 对应的 KV pages。`vFlow` 还能组合 GeMM、Softmax、Top-K、Gather、reduction、Mask 与 state update，表达 DoubleSparse、NSA block top-k、Quest、H2O 和 static pattern。

- 证据定位：论文 Section 3.1，Equations 1-4，Figures 3-4；Section 3.2，Figures 5-8 与 Appendix F operator table；项目 `docs/examples.md` 和 `vortex_torch/flow/algorithms.py`。

#### 5.2 `vTensor`：逻辑 tensor 与物理 layout 同时存在

`vFlow` 让程序员按单请求、逻辑 contiguous tensor 思考；`vTensor` 在底层附加 batch pointer、page indices 和 layout metadata。query 通常是 batch layout，K/V 与 named cache 使用 paged layout，临时中间量默认使用 ragged layout。compiler 根据 operator semantics 传播 shape 与 layout，再生成实际 kernel DAG。

这项设计的关键效果是：named cache 与 KV cache 共享 paging / allocation mechanism，prefix cache 复用时无需把 auxiliary summaries 拆到另一套地址空间。它仍要求算法遵守 page 作为 sparsity unit，并且跨 sequence operator 不在当前语义内。

- 证据定位：论文 Section 4.1，Equation 5；Section 4.2 对 query、KV、named cache 和 temporary tensor layouts 的说明；Appendix B 对 layout propagation 与 batch-dimension constraint 的讨论。

#### 5.3 Workload planning、fusion 与 approximate radix top-k

Vortex 在每个 decode iteration 已知 batch size 和 sequence lengths 后规划 GPU workloads。GeMM、elementwise 与 reduction 等 sequence-local operators 共享 chunk template；兼容的 operator 在 DAG 上做 greedy fusion，减少中间读写。

动态 top-k 是 indexer 的独立瓶颈。论文在 radix top-k 上加入 stochastic early termination：threshold bin 已收集足够高置信候选后停止完整 refinement，并从剩余 bin 中采样。再配合 order-preserving remap，作者在 recall@$k>0.97$ 的 microbenchmark 中报告平均 $1.49\times$、范围 $1.30\text{-}1.62\times$ 的 top-k kernel speedup。该优化引入近似 selection，需要在 end-to-end quality gate 中约束。

- 证据定位：论文 Sections 5.1-5.2；Appendix C kernel template；Appendix D.2-D.3，Figures 18-19。

#### 5.4 Attention backend：selector 之后仍需匹配模型 geometry

selector 最终输出 sparse block table。GQA 路径复用 FlashInfer 和 TensorRT-LLM MHA backend；MLA 路径支持 `trtllm_mla`，并为 vendor kernel 不覆盖的 geometry 增加 `cuda_mla`。论文说明 `trtllm_mla` 只支持固定 latent geometry 与 block size 32/64，`cuda_mla` 支持更一般 geometry 和最小 16-token block。

这也意味着 speedup 需要拆成两部分：

$$
\text{observed speedup}
=
f(\text{sparsity},\text{selector},\text{backend},\text{precision},\text{batch},\text{model}).
$$

当 full 与 sparse path 使用不同 backend 时，端到端差异无法只归因于 sparsity。GLM-4.7-Flash 正是这一情形。

- 证据定位：论文 Section 5.3；Section 6.2 footnote 1；项目 `vortex_torch/engine/sgl/attention_backend/{trtllm.py,trtllm_mla.py,triton_mla.py,cuda_mla.py}`。

#### 5.5 AI-agent loop：可执行搜索空间与固定评测 harness

论文包含两种 agent use case：

1. **One-shot innovation**：Claude Opus 4.7、Claude Sonnet 4.6 和 GPT-5.5 各生成 20 个 flow；先通过 RULER 4K retrieval 的 85% gate，再评测 AMC23，Pareto frontier 候选进入 AIME24。
2. **Long-horizon iteration**：Claude Opus 4.7 在 18 小时内执行 23 轮、92 次提交，每轮修改 flow 或系统配置并读取 mean@16 / throughput。

仓库把 flow contract、preflight、RULER gate、AIME runner 和 submission schema 放在 `AI/`、`.claude/` 与 `algorithm_scientist/`。这表明“agent 可操作的实验环境”是代码中的实际对象。论文同时允许 long-horizon loop 调整 KV dtype、skipped layers 等系统参数，最终方案仍属于 block top-k family，因此该实验更准确地验证了可执行实验闭环和 Pareto search。

- 证据定位：论文 Sections 6.1.1-6.1.2，Figures 9-11；Appendix E agent templates；项目 `AI/AGENTS.md`、`algorithm_scientist/README.md` 和 `algorithm_scientist/run_submission_aime24.py`。

### 6. 结论链条

1. Dynamic sparse attention 的完整成本包含 cache summary、query-dependent selector、top-k、block-table construction 与 selected attention。
2. `vFlow` 把算法拆成可组合 operators，`vTensor` 保留 paged/ragged layout semantics，使 selector 可以进入真实 decode loop。
3. Workload planning、fusion 和 approximate radix top-k 控制 indexer overhead，optimized backend 承担 selected attention。
4. Qwen3 实验表明，同一条 SGLang-based 路径可以把 block top-k / Quest 转化为长 decode 下的端到端吞吐与 P95 TPOT 收益。
5. MiniMax-M2.7 实验表明，收益在 229B、TP=4 规模仍然存在；参数读取与通信占 decode 时间的比例上升后，收益幅度随之缩小。
6. Agent 实验表明，该接口足以支持 coding agent 生成、编译、筛选和评测候选 flow；现有对照尚未分离模型能力、harness、参考材料和搜索预算各自的贡献。
7. 因此，论文最稳固的核心信号是“dynamic sparse-attention research infrastructure”：它把 selector 设计与 paged serving execution 放进同一可编程、可评测系统。关于 production universality、纯 sparsity 的 $4.7\times$ 收益和新算法自动发现仍需要更严格对照。

## 关键实验/定理

### 结果 1：Agent 可以通过固定接口生成并迭代可运行的 sparse flows

- 设置：Qwen3-1.7B，单张 NVIDIA H200 SXM；AMC23 / AIME24 最长生成 16K；三种 coding agent 各提交 20 个 one-shot algorithms；另有 Claude Opus 4.7 的 18 小时迭代。
- Baseline：SGLang full attention，以及 block top-k / Quest operating points。
- 指标：RULER accuracy、AMC23 / AIME24 mean@16、decode throughput、AST-based structural diversity。
- 结果：60 个 one-shot flows 均成功 compile / execute；通过 staged filtering 的候选在三个 benchmark 上达到 full-attention-level accuracy 和 $2\text{-}3.1\times$ throughput。18 小时 loop 在 AIME24 上达到 11,894 tok/s vs full attention 3,437 tok/s，mean@16 为 38.96 vs 38.54，即 $3.46\times$。
- 证据定位：论文 Section 6.1.1，Figures 9-10；Section 6.1.2，Figure 11；PDF pages 8-10。
- 对照是否可比：硬件、模型和 benchmark 对齐；long-horizon loop 同时调整 sparsity structure、block size、top-k、KV dtype 和 skipped layers，无法只识别 programming abstraction 或某个算法的贡献。
- 支持的最窄结论：Vortex 提供了足够稳定的 flow contract 和 benchmark harness，使 coding agent 能自动提交并搜索 accuracy-throughput frontier。
- 解读：最终方案收敛到 block top-k family，实验支持“自动实验与系统联合优化”，对“发现新的 sparse-attention mechanism”只提供探索性证据。

### 结果 2：Qwen3 dense model 获得端到端 decode 收益

- 设置：Qwen3-0.6B / 1.7B / 4B / 8B，H200 141GB；AMC23 与 AIME24，input 最长 4K、output 最长 16K；block size 16，attended blocks 32-256。
- Baseline：vendored SGLang v0.5.9 full attention；Vortex block top-k 与 Quest。
- 指标：offline generation throughput 与 accuracy budget 下的 Pareto frontier。
- 结果：在 5 percentage-point accuracy budget 下，block top-k 在 AMC23 / AIME24 最高为 $3.46\times / 3.60\times$，Quest 为 $2.73\times / 2.98\times$；在 1 pp budget 下，block top-k 仍为 $2.14\text{-}2.31\times / 2.42\text{-}3.60\times$。
- 证据定位：论文 Section 6.4.1，Figure 14；PDF page 12。
- 对照是否可比：同一模型、GPU、generation protocol 和 SGLang integration，implementation matching 比 GLM 对照更好；论文没有报告独立系统 run 的方差或置信区间。
- 支持的最窄结论：对所测 decode-heavy math workloads，Vortex-integrated block top-k / Quest 可以在可控准确率损失下获得真实 server throughput 提升。
- 解读：accuracy budget 是 speedup 的组成条件。最高值不能脱离具体模型、任务和 top-k operating point 单独使用。

### 结果 3：Synthetic P1D1 测试显示高负载下 P95 TPOT 降低

- 设置：Qwen3 series；synthetic 16K-token prompts；每请求生成 512 tokens；request rate 1-8 req/s；P1D1 disaggregation；attended blocks 160。
- Baseline：full attention。
- 指标：P95 time per output token (TPOT)。
- 结果：8 req/s 时 block top-k 最高降低 $11.7\times$，Quest 最高降低 $12.8\times$；4 req/s 时分别最高为 $11.8\times$ 与 $11.1\times$。
- 证据定位：论文 Section 6.4.2，Figure 16；PDF page 13。
- 对照是否可比：同一 synthetic workload 与 P1D1 setup；测试有意隔离 decode，未覆盖 prefill bottleneck、真实 arrival distribution 和多租户调度。
- 支持的最窄结论：在高 request rate、固定长 prompt、固定短 output 的 decode-isolated setting 中，降低每步 KV attention traffic 可以显著改善 tail TPOT。
- 解读：该结果适合作为 decode path 的 stress test，无法直接外推完整线上 request latency 或 agent session latency。

### 结果 4：GLM-4.7-Flash 的最高 $4.7\times$ 含有 backend 混杂

- 设置：GLM-4.7-Flash，单张 NVIDIA B200；AIME26；32K generation；rope-aware / rope-unaware sparse flow 与 Quest；block size 16/32/64。
- Baseline：full attention 使用 Triton MLA fallback；Vortex sparse flow 使用 optimized `cuda_mla`，因为 GLM head geometry 不受 vendor `trtllm_mla` 支持。
- 指标：mean@16、pass@4 / pass@8 与 end-to-end throughput。
- 结果：full attention mean@16 0.765、1,031 tok/s；rope-aware sparse design mean@16 约 0.752 时约 $4\times$，更紧预算最高 $4.7\times$；rope-unaware mean@16 降到约 0.60-0.63。
- 证据定位：论文 Section 6.2，Figure 12，尤其 footnote 1；Section 6.3 的 RoPE-component ablation；PDF pages 10-11。
- 对照是否可比：模型、任务和硬件一致，attention backend 不一致。对照同时测量 sparsity、block budget 与 CUDA-vs-Triton kernel 差异。
- 支持的最窄结论：Vortex 可以为 vendor kernel 未覆盖的 MLA geometry 实现 rope-aware sparse decode path，并在该组合路径上显著快于现有 dense fallback。
- 解读：$4.7\times$ 不能写成纯 sparse-attention algorithm speedup。RoPE-aware ablation 更可靠地支持“MLA selector 必须保留 decoupled positional component”。

### 结果 5：229B、TP=4 模型仍有收益，参数与通信流量压缩收益空间

- 设置：MiniMax-M2.7 229B，4 张 NVIDIA B200，TP=4；AIME26；32K generation；block size 16/32/64。
- Baseline：full attention。
- 指标：mean@16、pass@4 / pass@8 与 end-to-end throughput。
- 结果：full attention mean@16 0.83、3,341 tok/s；block top-k mean@16 0.84、4,110 tok/s，即 $1.23\times$，更紧 block budget 最高 $1.37\times$；Quest 在相近准确率约 $1.19\times$。
- 证据定位：论文 Section 6.4.1，Figure 15；PDF page 12。
- 对照是否可比：同一模型、GPU topology、task 与 TP setting；论文没有给出多个 backend 的逐项 breakdown，implementation matching 仍需 artifact reproduction。
- 支持的最窄结论：当 parameter movement 与 TP communication 占比上升时，sparse KV attention 的端到端收益会缩小，但在所测 229B model 上仍为正。
- 解读：这个结果比 headline maximum 更适合估计大模型 serving 上的现实收益范围。

### 结果 6：Kernel microbenchmark 将 selected attention 与 top-k 识别为可分离瓶颈

- 设置：Qwen3-0.6B 到 8B；batch 4/16；context 4K-32K；block top-k / Quest；另测不同 score distribution 下的 radix top-k。
- Baseline：dense attention kernel；standard radix top-k。
- 指标：per-kernel decode latency、recall@k、top-k latency。
- 结果：Qwen3-8B、batch 16、32K 时 sparse attention kernel 为 0.025 ms，dense 为 0.760 ms；approx radix top-k + remap 在 recall@$k>0.97$ 下平均 $1.49\times$，范围 $1.30\text{-}1.62\times$。
- 证据定位：论文 Appendix D.1-D.3，Figures 17-19；PDF pages 21-23。
- 对照是否可比：microbenchmark isolate individual kernels，适合定位成本；不能替代 full-model or server result。
- 支持的最窄结论：在这些 shapes 下，selected attention 的 kernel savings 足够大，且 approximate top-k 可以进一步降低 indexer cost。
- 解读：论文把 indexer/cache overhead 描述为 negligible；该判断来自所测 Qwen shapes。不同 selector complexity、page size 与 hardware 需要重新 profile。

## 证据链强度评估

### 强证据

- `vFlow -> vTensor -> backend` 的抽象边界在论文、文档与代码中可交叉定位，接口和实现对象清楚。
- Qwen3 的 SGLang-based end-to-end throughput frontier、MiniMax-M2.7 TP=4 scaling 和 Appendix kernel breakdown 共同支持“sparse selector 进入 serving stack 后可以获得实际 decode gain”。
- GLM rope-aware / rope-unaware ablation 清楚显示 decoupled RoPE component 对 MLA block selection 很重要。
- 项目仓库公开 flow examples、SGLang adapter、CUDA/Triton kernels 和 agent benchmark harness，为后续复现提供入口。

### 中等强度证据

- AI agent 可以生成、编译、筛选和评测 flow。公开仓库能够验证 harness 的实现；算法新颖性、prompt 设计与框架辅助仍相互耦合。
- Synthetic P95 TPOT stress test 清楚展示 decode bottleneck 下的收益，真实 arrival、prefill 与 scheduler interactions 尚未覆盖。
- Qwen3 channel-group finding 在 4B / 8B 上一致，但论文明确指出 g3 / g7 可能是 Qwen3-specific geometry。

### 需要谨慎的推论

- GLM-4.7-Flash 的 $4.7\times$ 同时包含 sparse selection 与 attention backend replacement。
- “production serving” 在当前证据中应理解为接入真实 SGLang serving stack 并做 end-to-end benchmark；论文没有生产流量、SLA、failure recovery 或 multi-tenant evidence。
- Agent search 的最好结果同时使用算法和系统 knobs，且最终回到 block top-k family；它还没有证明 autonomous system 能稳定发现跨任务泛化的新机制。
- Math / retrieval benchmark 上的 accuracy preservation 不能推出 tool-use、RAG、代码和对话 history 中的 evidence recall 同样保持。

## 本地讨论补充

### 1. 讨论收敛点

- Vortex 的核心贡献位于 selector / indexer 与 serving runtime 之间：它提供可表达、编译和评测多种 sparse-attention pattern 的系统接口，贡献重点是执行基础设施；具体 flow 主要组合已有 selector family。
- `vFlow` 的单请求 mental model 只是一层逻辑视图。真实执行仍由 `vTensor` 处理 batch pointer、paged cache 和 ragged intermediates。
- `forward_cache` 构造可复用 page summary，`forward_indexer` 每个 decode token 生成 sparse block table；attention backend 只负责对选中 blocks 做高效 attention。
- Agent loop 的长期价值在于可执行 research environment：候选必须 compile、通过质量 gate，并在同一 harness 上返回 throughput。当前论文对 novel algorithm discovery 的证据仍有限。
- GLM-4.7 的 $4.7\times$ 需要始终附带 backend footnote。它证明“Vortex 组合路径比现有 fallback 快”，没有隔离纯 sparsity contribution。

### 2. 修正后的理解

原笔记把 Vortex 概括为“可编程 sparse attention production serving”，其中 production 容易引出超出证据的解释。更稳妥的表述是：Vortex 把 dynamic sparse attention 编译到 SGLang-based paged decode path，并提供端到端 server benchmark。生产可用性仍需要真实 trace、SLA、failure handling、version compatibility 和 external reproduction。

AI agent 部分也需要按两层理解：

$$
\text{agent research value}
=
\text{programmable search space}
+
\text{automated execution/evaluation loop}.
$$

论文已经较强地展示第二项，也展示第一项足以产生结构多样的 flows。对于“新算法”的判断，还需要 holdout workloads、搜索预算对齐、human baseline、novelty review 和跨模型 transfer。

项目快照包含 dense prefill execution path，以便完整请求能够进入 decode；论文限制指的是 sparse prefill optimization 尚未支持。二者语义可以同时成立：prefill 可以运行，sparsity 只作用在 decode。

### 3. 后续复验指标

- 在同一 attention backend 上对比 dense 与 sparse MLA，单独隔离 selector、top-k、block gather 和 attention kernel。
- 除 offline tok/s 外，同时报告 TTFT、TPOT、goodput、P50/P95/P99、OOM / preemption、prefix-cache hit 和 scheduler fairness。
- 使用 BrowseComp、SWE-bench agent traces、RAG、多轮 tool-use 和长对话 history 评测 evidence recall 与任务成功率。
- Agent search 增加 fixed-budget human expert、random search、Bayesian optimization 与 no-reference ablation。
- 把 generated flow 在 unseen model、task、prompt length 和 hardware 上复验，测量 Pareto frontier transfer。
- 固定 code commit、SGLang / FlashInfer / TensorRT-LLM version、container 和 launch configuration，执行独立 artifact reproduction。

## 主要启发

1. Dynamic sparse attention 的系统瓶颈经常落在“如何产生 sparse indices”，attention kernel 只是后半段。
2. page-centric IR 可以成为算法与 serving runtime 之间的稳定接口；类似思想也适用于 KV compression、learned retrieval 和 cross-layer index sharing。
3. 系统 speedup 需要拆解 algorithm、kernel、backend、precision 和 workload。任何一项变化都可能改变 headline ratio。
4. Agent for systems research 的有效环境需要编译约束、低成本 preflight、质量 gate、端到端 benchmark 和持久实验记录；单纯生成代码还不足以形成可靠发现。
5. 大模型 TP setting 中 parameter / communication traffic 会稀释 KV optimization 的收益，系统优化应先测完整 decode breakdown。

## 局限

- Vortex v1 只对 decode 使用 sparse attention；prefill 仍走 dense path，training backward 未支持。
- 当前抽象以 attention model、显式 KV cache 和 page-level sparsity 为中心，RNN / Mamba state 与跨 sequence operator 未覆盖。
- 主要实验集中在数学与 retrieval，缺少真实 agent workflow、生产 trace 与多租户 serving。
- GLM-4.7 headline comparison 存在明确 backend confound。
- AI-agent loop 没有 human / random-search compute-matched baseline，也没有跨任务 holdout generalization。
- 论文没有报告独立 system-run variance、能耗、完整成本或 artifact evaluation。
- 仓库依赖 vendored SGLang v0.5.9 和特定 CUDA backend；升级兼容性与非 NVIDIA portability 尚未展示。

- 与 [DeepSeek Sparse Attention](/papers/2025-09-29-deepseek-v3-2-exp-dsa-long-context-efficiency/)、[MiniMax Sparse Attention](/papers/2606.13392-minimax-sparse-attention-m3/) 和 [HiLS](/papers/2607.02980-hils-attention-infinite-context/)：这些工作把 selector / hierarchy 进入模型结构或训练；Vortex 主要为 inference-time selector 与 selected attention 提供执行接口。将 trainable selector 接入 Vortex-style runtime 需要补齐模型专属 cache 与 kernel semantics。
- 与 [FlashMemory](/papers/2606.09079-flashmemory-deepseek-v4-lookahead-sparse-attention/)：FlashMemory 预测哪些 DeepSeek-V4 CSA chunks 应驻留 GPU，Vortex 处理 selected blocks 如何在 paged decode 中执行。一个控制 physical residency，另一个控制 selector program 与 execution。
- 与 [GLM-5.2](/papers/2026-06-16-glm-5-2-long-horizon-tasks/)：GLM-5.2 的 IndexShare / IndexCache 通过跨层复用降低 indexer 成本；Vortex 通过 programmable cache/indexer operators 和 fusion 降低实现与执行成本。两者共同把 selector 本身视为一等系统开销。
- 与 [Parrot](/papers/2405.19888-parrot-semantic-variable-llm-serving/) 和 [Span Query](/papers/2511.02749-span-queries-cache-attention-locality/)：Parrot 暴露 application DAG，Span Query 暴露 span/expression locality，Vortex 暴露 attention-level sparse program。三者分别在 workflow、prompt structure 和 decode attention 层提供 optimization interface。
- 与 [ThunderAgent](/papers/2602.13692-thunderagent-program-aware-agentic-inference/)：共享 [Beidi Chen](/authors/beidi-chen/) 与 CMU Infini AI Lab 线索；ThunderAgent 调度 LLM/tool program phase，Vortex 优化 decode attention。当前关系是可组合的系统层级，尚无直接 integration evidence。
- 与 [TIM / VeXact](/papers/2605.14220-training-inference-mismatch-llm-rl/)：sparse selector、approx top-k、RoPE/MLA layout 和 rollout/trainer backend difference 都可能改变 sampled-token logprob。若 Vortex path 用于 RL rollout，训练侧必须决定如何重算同一 sparse pattern 或校正 mismatch。
