## 一句话结论

Leyline 在 agent policy 与 KV Cache 之间增加语义编辑通道：policy 用 `(span, replacement, mode)` directive 声明需要修改的历史范围和语义保证，serving 层保留未修改前缀、重算 replacement，并用 RoPE $\delta$-rotation 重标 MLA 后缀 KV 的位置，从而在 `AMORTIZE` 模式下减少上下文编辑后的重复 prefill，在 `FORGET` 模式下回退到 prefix-trimmed re-prefill 实现真正遗忘。

本地评价：论文最重要的贡献是把 cache mutation 提升为 agent-facing contract，并明确区分位置摊销与语义遗忘；$\delta$-rotation kernel 明确继承自 Irminsul。机制实验给出 radix hit rate `49.6% → 60.8%`，最佳观测单元 $C=8$ 的 p50 下降 241 ms。policy 实验来自标准 re-prefill，论文报告 `10/32 → 15/33`，精确差值约 14.2 pp；Table 2 的逐任务 treatment 行只合计到 `14/32`，额外 trial 没有进入表内，因而只适合作为小样本 policy signal。`AMORTIZE` 保留原 span 对后续 KV 的历史影响；即使在 MLA 内，Appendix G 的长轨迹 first-token agreement 也呈现明显模型差异。GQA / MHA 的高效实现、联合 policy×kernel 实验和公开 artifact 仍是主要缺口。

## 阅读目标与判断边界

本笔记关注：

1. agent 主动编辑历史时，传统 prefix cache 为什么会丢失 edit point 后的大量已算 KV。
2. directive、`AMORTIZE` / `FORGET` 和 $\delta$-rotation 分别提供什么语义与系统保证。
3. 机制实验、policy 实验和真实轨迹分别支持哪些结论，以及三组证据能否合并归因。

判断边界：

- `AMORTIZE` 的证明对象是旧 raw key 在新绝对位置上的 RoPE 相位；生成结果是混合 cache 状态，通常不对应任何普通 prompt 的单次完整 prefill。
- `FORGET` 走 prefix-trimmed re-prefill，提供删除、纠错或合规场景所需的语义边界，同时保留重算成本。
- 高效 kernel 的主要实证对象是 MLA。GQA 只有 full-width K rotation 的离线原型，输出层 contract 很弱；MHA 只有代数外推。两者都没有 production serving kernel，boundary recomputation 仍是候选方案。
- 论文将机制与 policy 分两条腿验证，没有给出 splice kernel 加速截断 policy 的联合消融。Section 5、Table 2、Limitations 与 Appendix A 后半段写明 policy 两臂走 standard re-prefill；Appendix A 前半段另有“applies the splice via $\delta$-rotation”的冲突表述，本笔记采用多处一致的 standard re-prefill 口径。
- 论文描述了约 200 LOC SGLang RadixCache patch，但公开仓库当前无法从官方来源定位。

## 论文脉络

### 1. 研究问题、背景和价值

传统 LLM serving 把 prompt 视为单调增长序列。token 完成 prefill 后，内容和绝对位置通常保持不变，因此 radix / prefix cache 可以从第一个 token 开始匹配连续前缀，后续请求只计算新增 suffix。

长程 agent 会主动重写历史：失败工具输出被替换，旧日志被截断成 stub，过期调查块被摘要，retry 可能丢弃一段轨迹。设原始 prompt 为

$$
P=A\Vert B\Vert C,
$$

policy 将中间 span $B$ 替换为更短的 $R$，新 prompt 为

$$
P'=A\Vert R\Vert C.
$$

radix cache 只能稳定命中 $A$。即使 $C$ 的 token 内容保持不变，它的绝对位置已经改变，原有 RoPE key 也锚定在旧位置；常规 harness 会从 edit point 开始重新 prefill $R\Vert C$。编辑越靠前、轨迹越长，重复计算越多。

论文进一步区分两个 cache 问题：自然发生的相同内容位置迁移属于 position-invariant reuse；policy 明确要求删除或替换 span 属于 policy-driven mutation。Leyline 聚焦后者。证据定位：Section 1，Figure 1，PDF pp.1-2；Table 1，PDF p.3。

### 2. 已有解决方案与不足

- Prefix / radix cache 复用连续前缀；任意中段编辑会截断后续命中。
- H2O、SnapKV、StreamingLLM 等 kernel-side eviction 根据系统或注意力信号自主选择 token，缺少 agent policy 可审计的 span-level mutation 接口。
- LMCache 的 Pin、Clear、Move、Compress、Lookup 操作物理 KV block 和存储层级；它没有定义语义 span 编辑后的位置正确性。
- CacheBlend、EPIC 通过选择性重算支持 MHA / GQA 的非前缀复用；Irminsul 用 content hash、CDC chunk 和 $\delta$-rotation 处理 MLA 中自然位置迁移。
- 供应商 context editing API 通常在消息层修改历史并执行 re-prefill，能够获得替换后 prompt 的语义，却会丢失 edit point 后的缓存工作。

Leyline 将 policy intent、语义模式与架构特定 kernel 分层：上层声明修改范围和需要的保证，下层选择 in-place splice 或 re-prefill。证据定位：Section 2，Table 1，PDF p.3。

### 3. 作者可能的思考路径

以下为本地分析的受约束重建：

1. 先观察 agent 每轮重新渲染 history 的路径，发现一次中段 message edit 会让 radix hit 在 edit point 之后归零。
2. 将“相同内容自然移动”和“policy 主动修改”分开，确认后者需要显式 agent→serving 控制通道。
3. 复用 Irminsul 在 MLA 上验证过的 RoPE 位置校正，把 content-hash 触发改成 policy directive 触发。
4. 发现原 span 已经进入后续 token 的 hidden state；单纯旋转后缀 key 只能校正位置，无法消除原内容的历史影响，因此把接口拆成 `AMORTIZE` 与 `FORGET` 两种 mode。
5. 用机制 microbenchmark 验证缓存和延迟，再用简单截断 policy 验证 span signal 是否能产生 agent-level 价值，形成两条独立证据链。

### 4. 核心假设或切入点

Leyline 的 splice 路径依赖四个条件：

1. **显式编辑边界**：policy 能把消息级决策稳定映射为 rendered prompt 中的 token span。
2. **RoPE 可校正性**：position shift 可通过旋转群闭包在缓存 key 上做 closed-form correction。
3. **可接受的持久影响**：选择 `AMORTIZE` 时，部署方接受原 span 已经写入 downstream hidden state 这一事实。
4. **存在重算 headroom**：vanilla radix cache 在 edit 后仍有较长、内容不变的 suffix；已有命中很高时，splice 可节省的工作很少。

前两项决定机制能否执行，第三项决定语义是否适用，第四项决定性能收益。

### 5. 方法 / 系统框架

#### 5.1 Directive：把 policy intent 显式化

directive 定义为四元组：

$$
D=(s_{\mathrm{start}},s_{\mathrm{end}},R,m),
$$

其中 $[s_{\mathrm{start}},s_{\mathrm{end}})$ 是原 rendered prompt 的 token 区间，$R$ 是 replacement tokens，$m\in\{\texttt{AMORTIZE},\texttt{FORGET}\}$ 是语义模式。同一 turn 可以提交多个互不重叠的 directives；所有 span 使用原 prompt 坐标，kernel 从左到右携带累计位移，重叠 span 在 apply-time 拒绝。attention-sink 部署还要求 edit 起点位于 sink prefix 之后。production runtime 需要让一组 directives 原子提交，并在中途失败时回滚。证据定位：Section 3.1，PDF pp.3-4；Appendices C、O。

policy SDK 暴露 `Policy.transform(messages, turn_idx) -> messages`。Leyline 对比上一 turn，计算 message diff 并生成 token directive。信号可以来自 turn counter、手写规则、content matcher 或 learned detector；kernel 不检查 policy 的理由。证据定位：Section 3.4，PDF p.5。

#### 5.2 两种 mode 对应两种语义

设 replacement 相对原 span 的长度变化为

$$
\Delta=|R|-(s_{\mathrm{end}}-s_{\mathrm{start}}).
$$

`AMORTIZE` 校正 edit 后 suffix 的位置，并保留 downstream `K_nope` 与 `V`。这些状态在原 span 存在时已经计算，因此输出继续携带原内容的历史影响。新的 stub 会进入显式 token 序列，缓存状态同时保留已传播到 downstream state 的旧信息。若原 prompt 为 $A\Vert B\Vert C$、replacement 为 $R$，状态结构可写成

$$
KV_A^{\mathrm{old}}
\Vert KV_R^{\mathrm{fresh}}(A)
\Vert T_\Delta\!\left(KV_C^{\mathrm{old}}(A,B)\right).
$$

这是 prefix、fresh replacement 与旧 downstream state 组成的混合 cache。它适用于低成本缩短展示历史、减少重复 prefill，并要求调用方接受 tensor-position contract 与原内容的持久影响。

`FORGET` 从保留前缀后重新 prefill replacement 和 suffix。敏感信息删除、错误工具输出修正、retention-mandated deletion 等场景需要这条路径。directive 层的增量价值是让语义意图可声明、可审计；kernel 性能增量集中在 `AMORTIZE`。证据定位：Section 3.1，PDF p.4。

#### 5.3 MLA 上的 $\delta$-rotation

MLA 将缓存 key 分成 position-free 部分 $K_{\mathrm{nope}}$ 和使用 RoPE 的位置部分 $K_{\mathrm{pe}}$。对原位置 $i\ge s_{\mathrm{end}}$ 的 suffix token，splice 后逻辑位置变成 $i+\Delta$。Leyline 更新：

$$
K^{\mathrm{new}}_{\mathrm{pe}}[i+\Delta]
=
\mathcal R(\Delta)K^{\mathrm{old}}_{\mathrm{pe}}[i].
$$

因为

$$
\mathcal R(\Delta)\mathcal R(i)=\mathcal R(i+\Delta),
$$

对固定的旧 raw key，旋转后的 $K_{\mathrm{pe}}$ 具有新位置对应的 RoPE 相位。更完整地写：

$$
K_{\mathrm{pe}}^{\mathrm{splice}}[i+\Delta]
=\mathcal R(i+\Delta)k_{\mathrm{raw}}^{\mathrm{old}}[i],
$$

而替换后 prompt 的完整 re-prefill 会产生

$$
K_{\mathrm{pe}}^{\mathrm{edit}}[i+\Delta]
=\mathcal R(i+\Delta)k_{\mathrm{raw}}^{\mathrm{edit}}[i+\Delta].
$$

编辑通常使 $k_{\mathrm{raw}}^{\mathrm{edit}}\ne k_{\mathrm{raw}}^{\mathrm{old}}$，因此旋转证明覆盖位置相位，不覆盖 edited-prompt state equivalence。论文测试的 MLA 配置使用 64 维位置 band；该维度来自所测模型配置，MLA 接口可以采用其他维度。DSv2-Lite 的物理 pool 保存 `c_KV` latent 与 $K_{\mathrm{pe}}$，$K_{\mathrm{nope}}/V$ 是语义解释中的逻辑展开。多次 edit 的旋转按 $\mathcal R(\Delta_1)\mathcal R(\Delta_2)=\mathcal R(\Delta_1+\Delta_2)$ 组合。证据定位：Sections 3.1-3.2，Equation 1，PDF p.4；Appendix U。

#### 5.4 Serving 集成

一次 directive 被分成三段执行：

1. edit 之前的 prefix 继续由 radix cache 命中。
2. 被替换 span 的 slots 被释放，replacement $R$ fresh prefill 到新 slots。
3. edit 之后的 suffix slots 执行 $K_{\mathrm{pe}}$ rotation 和逻辑位置重索引。

Role A 包装当前请求的 `match_prefix`，临时注入 borrowed slots，并在请求结束后释放。SGLang Role B 把修正后的 token-prefix→slot 映射插入 radix trie，再走原生 `match_prefix`，把 slot 生命周期交给 trie，让相同新 prefix 的未来请求继续发现这些 KV。content-hash side index 与 anchored content-defined chunking（CDC）负责首次寻找 donor suffix；Role B 负责后续原生 radix 发现。Appendix B 的早期纯 Gear-hash chunker 在小 prompt 上得到 0 个 splice chunk，说明稳定 chunk boundary 也是性能成立条件。

RoPE pairing convention 同样属于正确性条件：DSv2-Lite 使用 interleaved pairing，Llama / Qwen 风格使用 NEOX half-split，kernel 必须按 layer 读取相应配置。论文描述的实现包含约 200 LOC RadixCache patch 和 content-hash side index；当前公开 artifact 尚无法定位。证据定位：Section 3.3，Figure 2，PDF pp.4-5；Appendices B、P、R。

#### 5.5 数值与架构边界

rotation 计算默认使用 fp32，结果仍写入 bf16 KV pool。论文测得 bf16 storage 带来约 1%-3% per-K-entry error floor；50-step replay 报告 48/50 的 cross-arm first-token agreement，Section 4 / Appendix Q 将 reference 标为 full-prefill，Section 5 / Appendix T 将其标为 radix arm。fp32 rotation 能降低旋转计算误差，无法消除 bf16 存储误差。

MLA 把 position 集中在较小 $K_{\mathrm{pe}}$ band，提供最干净的高效路径。Appendix H 的 Table 8 只有 MLA 与 GQA 行，MHA 仅有逐 head 代数外推。两个 GQA live-model 单 token microbench 显示语义 contract 很弱：Minitron 在 8 个 references-diverge trials 中只有 1 次跟随 full-context；Qwen3-4B 在 6 个分歧 trials 中 0 次跟随 full-context、6 次跟随 re-prefill。作者提出的 chunk-boundary recomputation 尚未实现或测量。ALiBi、NoPE 与 learned absolute position 也未覆盖。证据定位：Sections 4、6，PDF pp.6-7、9-10；Appendix H，Tables 8-9；Appendix Q。

### 6. 结论链条

1. Agent history 的中段编辑会让 prefix cache 在 edit point 后丢失命中，即使大量 suffix token 内容保持不变。
2. Policy 比 storage layer 更早知道哪些语义 span 应被替换，因此需要 agent-facing cache-edit channel。
3. Directive 将 span、replacement 和语义 mode 绑定；`AMORTIZE` 与 `FORGET` 明确区分位置摊销和真正遗忘。
4. MLA 的 RoPE 位置 band 可以用 $\delta$-rotation 重标，保留未改 prefix 和已算 suffix KV。
5. 机制实验支持特定 workload 下的 cache-hit 与 re-prefill 延迟收益，policy 实验提供简单 context truncation 可能帮助部分长任务的小样本信号；两条证据尚未合并为联合系统结论。

## 关键实验/定理

### 结果 1：splice 在受控 message-edit workload 中恢复 suffix cache hit

- 设置：DeepSeek-V2-Lite，单张 H100，greedy decode；16 sessions，每个 session 6 turns；system prompt 约 4096 tokens，每 turn 约 2048 tokens，末轮约 17K prompt；并发 $C\in\{1,4,8,16\}$。
- Baseline：关闭 radix cache；标准 SGLang radix；Leyline splice。
- 指标：replay cache-hit ratio；p50 end-to-end latency；rotation kernel time。
- 结果：标准 radix 为 49.6%，splice 为 60.8%，所有并发下均增加 11.2 pp。p50 延迟分别为：$C=1$ 时 4087→4036 ms，$C=4$ 时 4729→4644 ms，$C=8$ 时 5533→5292 ms，$C=16$ 时 7166→7211 ms。最佳观测单元 $C=8$ 下降 241 ms（4.4%），累计 kernel time 不超过 2.9 ms/run。
- 证据定位：Appendix B，Table 3，PDF pp.15-18。
- 对照是否可比：三臂使用同一 SGLang scheduler 与 workload，mechanism 对照较强；prompt 是合成多主题 message edit，跨请求 discovery 和真实 policy 分布仍有限。
- 支持的最窄结论：在 17K、内容不变 suffix 较长的 MLA message-edit workload 上，in-place splice 能稳定恢复 11.2 pp cache hit，并在 prefill contention 较高的 $C=8$ 单元降低 p50。
- 解读：收益随并发非单调。$C=16$ 已进入 decode-dominated 区域，节省的 prefill 没有继续移动 p50；cache-hit 增加也不自动转化为端到端收益。

### 结果 2：截断旧工具输出改善少数长程 debug-gym 任务

- 设置：JoyAI-LLM Flash，H200 TP=4，SGLang；8 个 debug-gym `mini_nightmare` tasks，4 seeds，最多 50 agent steps。
- Baseline：`keep_all`，32 trials。
- Treatment：`truncate_older_than(n=2,max_chars=200)`，33 trials；旧 tool message 被替换为保留首尾的 200-character stub。
- 指标：hidden-test solve rate。
- 结果：论文 headline 为 10/32（31.25%）→15/33（45.45%），精确差值约 14.2 pp。Table 2 的八个 treatment 行相加得到 14/32（43.75%）；作者说明 treatment 多出一个 counter trial，但 counter 行仍显示 4/4，额外 trial 没有进入逐任务表。31 个可靠配对 cells 中，treatment 9 胜、baseline 5 胜，17 个结果相同。主要差异来自 `shopping_cart` 0/4→3/4 和 `sum_tree` 1/4→2/4。
- 证据定位：Section 5，Table 2，PDF pp.7、9；Appendix A，PDF p.14。
- 对照是否可比：Section 5、Table 2 caption、Limitations 与 Appendix A 后半段均写明两组走 standard re-prefill，主要变化是 message policy；Appendix A 前半段存在 splice 表述冲突。样本少、只测一个 threshold，逐任务表与 headline 分母无法完全核对，未报告置信区间或显著性。
- 支持的最窄结论：这组 debug-gym trials 提供了“截断旧 bash 输出可能帮助较长任务”的小样本信号；逐任务汇总与 headline 尚未完全对齐，效果大小需要扩大配对样本复验。
- 解读：按 9 胜、5 负的 discordant pairs 做本地 exact McNemar 双侧检验约为 $p=0.424$，当前证据不足以建立稳定 policy gain。两组的主口径均未使用 splice，因而无法支持 Leyline kernel 改善 solve rate 或降低该 policy 的端到端延迟。

### 结果 3：真实轨迹显示收益取决于 radix headroom，数值一致性受 bf16 floor 限制

- 设置：50-step `shopping_cart` debug-gym trace，prompt 从 334 增长到约 28K，$C=1$。
- Baseline：标准 SGLang RadixCache。
- 指标：sum end-to-end time、cache hit、first-token agreement。
- 结果：full configuration 从 52.65 s / 27.6% hit 变为 49.85 s / 27.8% hit，wall time 下降 5.3%。关闭 Role B L2、保留基础 splice 与 fp32 rotation 后为 49.62 s，说明 L2 在该轨迹上没有可测速度收益。论文将约 95% timing win 归于 fp32 rotation mitigation，但没有报告 `fp32 off` arm，公开数字无法复算这一比例。论文另报 48/50 的 cross-arm first-token agreement；Section 4 / Appendix Q 把 reference 写成 full-prefill，Section 5 / Appendix T 写成 radix arm。另一条 radix hit 达 91.6% 的轨迹中 splice 慢 0.6%，20/20 输出相同。
- 证据定位：Section 5，PDF pp.7-8；Appendix T，PDF p.28；Appendix Q。
- 对照是否可比：同 trace 的 bundle 对照直接，但单轨迹没有重复次数或置信区间；关闭 L2 的消融仍同时包含基础 splice 与 fp32 rotation，无法进一步拆分二者。两条 trace 的 radix headroom 差异很大。
- 支持的最窄结论：该低-hit 轨迹支持 full bundle 观察到少量 wall-time 改善，并支持 Role B L2 timing-neutral；证据无法把剩余改善分配给 fp32 rotation 或基础 splice。高 radix-hit 轨迹没有收益，bf16 KV storage 仍可能造成低 logit-margin 下的 token 分歧。
- 解读：Leyline 的目标是减少重复 prefill compute / writes，Role B trie pin 不降低 peak allocator watermark。该机制应按 cache reuse primitive 解读，KV 容量压缩需要单独机制。

### 结果 4：长轨迹 output fidelity 在不同 MLA 模型上差异很大

- 设置：同一条 `sum_tree` 长轨迹、相同截断 policy、每步 greedy decode 128 tokens；四个 MLA 模型最多运行 50 agent steps，后期每 turn 包含 2-8 个 edits。OOM step 从有效样本中排除。
- Baseline：保留原内容的 full-context reference；Leyline `AMORTIZE` replay。
- 指标：Leyline 相对 full-context 的 first-token agreement，分别统计 single-edit 与 multi-edit turns。
- 结果：DSv2-Lite 为 16/16（100%）与 33/33（100%）；GLM-4.7-Flash 为 13/16（81%）与 26/29（90%）；Moonlight-16B-A3B 为 9/16（56%）与 13/23（57%）；JoyAI-LLM Flash 为 2/16（12%）与 1/27（4%）。论文观察到部分 token divergence 仍能保留 tool-name agreement。
- 证据定位：Appendix G，Table 7，PDF pp.20-21。
- 对照是否可比：同一轨迹和 policy 有利于比较模型敏感性；各模型有效 step 数受 OOM 与提前终止影响，不能把百分比解释为同规模独立重复实验。
- 支持的最窄结论：MLA 的位置代数成立不自动带来长轨迹 token fidelity。DSv2-Lite 在该轨迹上稳定，Moonlight 与 JoyAI 对混合 cache 状态明显敏感；上线前需要逐模型 canary、logit-margin 分桶和周期性 re-prefill 策略。

## 本地讨论补充

### 1. 讨论收敛点

- Agent Workflow 的 cache state 具有语义版本。message list、rendered tokens、KV pages、workflow node input 和 speculative branch 需要绑定到同一 version；任一层发生 edit 后，其他层必须选择校正、定向重算或失效。
- `AMORTIZE` 更接近“修改显式历史并保留已经传播的内部状态”，适合上下文展示压缩和计算摊销。纠错、隐私删除与安全回滚需要 `FORGET`。
- SPORK rejected probe 属于 branch-local 临时状态，通常直接 cancel/free；Leyline 更适合已经 commit 到 canonical history 的 span。

### 2. 修正后的理解

- Leyline 提供的是 agent→cache mutation control plane。LMCache 一类系统可继续负责 block storage/movement，policy 负责 span 和 mode，架构 kernel 负责位置与状态正确性。
- splice 节省 re-prefill compute 和 KV writes，Role B 会把 slots pin 在 trie 中，因此它不直接降低峰值 KV pool occupancy。
- 三篇组合时，Grape 管已知 task 计算，SPORK 管在线 action speculation，Leyline 管跨 turn state mutation；它们共享 GPU batch 与 KV pages，需要统一 admission 和版本协议。

### 3. 后续复验指标

- 同一真实 agent trace 上的 `keep_all`、re-prefill truncation、`AMORTIZE` splice truncation、`FORGET` 四臂对照。
- edited-prompt logits、full-context logits 与 Leyline logits 的 KL / common-prefix / task outcome，并按 logit margin 分桶。
- message-boundary 与 mid-message edit、正负 $\Delta$、多 directive、1000+ turn 的累计漂移。
- GQA / MHA boundary recomputation 的额外 FLOPs、cache hit、P50/P95/P99 与 peak KV occupancy。
- Grape incremental prefill 已经消费某个 span 后发生 Leyline edit 时，依赖 node 的定向失效与重算成本。

### 4. 本次复核后的决策框架

Leyline 需要同时维护三份状态账本：

1. **Transcript state**：用户和调试器看到的 messages 与 replacement stub。
2. **Semantic state**：suffix KV 已经吸收的历史影响；`AMORTIZE` 保留旧影响，`FORGET` 重建该状态。
3. **Physical cache state**：slot、position、radix ownership、reference count 与 tenant scope。

部署决策可以压缩为：

| 需求 | mode | 语义 reference | 主要代价 |
| --- | --- | --- | --- |
| 缩短展示历史，同时允许旧信息继续影响后续状态 | `AMORTIZE` | 原 full-context 的旧 raw state，经位置重标后继续使用 | replacement prefill、rotation、reindex 与 fidelity 风险 |
| 纠正错误工具结果、删除敏感信息或满足 retention 要求 | `FORGET` | 编辑后 prompt 的 honest re-prefill | 从 edit point 开始重算 suffix |
| 当前模型、位置编码或数值条件尚未通过 canary | `FORGET` | 编辑后 prompt 的 honest re-prefill | 放弃 splice 节省，保留可审计语义 |

这张表也限定了论文贡献：Leyline 提供 mode-aware cache-edit contract 与 MLA serving integration；删除策略的学习位于 signal-side，当前 truncation 规则只是一个示例。

## 主要启发

- Agent runtime 需要 prompt channel 之外的 cache-edit channel，把 policy 的语义知识转为 serving 可执行的 directive。
- KV 优化需要同时说明计算等价、缓存状态语义和错误回退；位置正确只覆盖其中一层。
- `mode` 是重要的 API 设计：性能路径与真正遗忘使用不同 contract，调用方需要显式选择。
- 旋转代数正确、单步 token agreement 与长轨迹 task fidelity 是三个独立验证目标；production gate 需要逐模型测量。
- 跨论文系统可以把 TaskFlow、speculative branch 和 KV directive 统一到一个带版本、提交和回滚的 execution IR。

## 局限

1. 高效 kernel 的主证据集中在 MLA；GQA 只有输出 contract 较弱的离线原型，MHA 只有代数外推，非 RoPE 位置编码和 sequence-compressed KV 仍待实现。
2. `AMORTIZE` 保留原 span 对 downstream hidden state 的影响，适用语义明显窄于任意 context editing。
3. Policy leg 只有 8 tasks×4 seeds、一个截断 threshold，headline 与逐任务行无法完全核对，且没有与 splice 联合运行。
4. 合成 mechanism workload 为 edit 后相同 suffix 提供了较大 headroom；241 ms 只出现在最佳观测单元 $C=8$，高 radix-hit 真实轨迹显示收益可归零。
5. 四模型 long-horizon replay 中，Moonlight 与 JoyAI 的 first-token agreement 明显下降；100 次 chained rotations 的 relative-L2 约为 $2.6\times10^{-2}$，千次级轨迹未测，bf16 KV floor 仍会造成 argmax flip。
6. Splice 不降低 peak allocator watermark；cross-tenant warm-start 只在窄配置激活，更高 tenant/concurrency 出现 candidate-filter degenerate。
7. PIN、SHARE、DECAY、SCRATCH 等后续 verbs 仍是设计议程，并引入跨 tenant 泄漏、恶意 pin 与资源耗尽风险。
8. 单条 real-trace 的 `fp32 off` arm 缺失，论文声称的 95% timing attribution 无法从公开数字复算；48/50 agreement 的 reference 标签也不一致。
9. 公开 artifact 当前不可定位，约 200 LOC patch、manifest 和策略代码难以独立复验。

## 跨论文关系

- 与 [Grape](/papers/2026-07-13-grape-micro-task-agentic-workflow-serving/)：Grape 在预声明 DAG 中提前执行下游 prefill，并管理 append-only micro-task KV；Leyline 处理 canonical history 已发生的 span mutation。二者组合需要更新 sequence length、partial-edge 进度、batch cost model、KV ownership 和依赖 node version。

- 与 [Span Query](/papers/2511.02749-span-queries-cache-attention-locality/)：Span Query 让客户端声明可重排 message spans，以 expression tree 提升 locality；Leyline 让 policy 声明可替换 span，并在 cache 层处理 mutation 后的位置与重算语义。
- 与 [ThunderAgent](/papers/2602.13692-thunderagent-program-aware-agentic-inference/)：ThunderAgent 管 tool wait 期间的 KV pause / restore 和 program lifecycle；Leyline 增加 message edit 对 KV state 的显式控制。完整 runtime 需要同时管理等待、编辑、版本和回收。
- 与 Irminsul：同一作者团队与同一 $\delta$-rotation 基础。Irminsul 由 content hash 触发自然位置迁移的 KV reuse，Leyline 由 agent policy 触发主动 mutation。
