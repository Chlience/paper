## 一句话结论

Gemma 4 是 Google DeepMind 的新一代 open-weight 多模态模型族，覆盖 E2B、E4B、12B Unified、26B-A4B MoE 和 31B Dense：报告把 dense / MoE 架构、thinking mode、$128\mathrm{K}$ / $256\mathrm{K}$ 长上下文、p-RoPE、global layer 的 unified K/V、QAT、MTP drafter、12B encoder-free 多模态路径和官方 benchmark 结果放在同一个系统叙事里。它的价值在于把“能力、内存、延迟、部署硬件和多模态输入”同时作为 open-weight 模型设计变量；可信度边界在于训练数据规模、post-training / RL recipe、MTP 真实服务延迟和安全评测细表披露有限，多数性能结论来自官方报告。

## 论文脉络

### 1. 研究问题、背景和价值

Gemma 4 的核心问题是：open-weight 模型要进入真实部署场景时，模型报告不能只回答“榜单分数是否高”，还要回答模型能否在本地设备、移动端、consumer GPU、workstation 和多模态 agent workload 中稳定运行。

这类场景同时拉动四个约束：

1. 能力约束：需要 STEM、coding、instruction following、long-context retrieval、视觉、音频和 agentic function calling。
2. 内存约束：long-context KV cache、vision / audio encoder、MoE weights 和 dense weights 都会进入部署成本。
3. 延迟约束：多轮对话、tool use、agentic coding 和长输出推理需要更高 decode throughput。
4. 发行约束：open-weight 模型需要给不同硬件提供可用 checkpoint、量化版本和稳定模型卡。

Gemma 4 把这些约束统一为一个模型族设计问题。E2B / E4B 面向移动端和边缘设备，12B Unified 面向中等规模多模态统一架构，26B-A4B 通过 Mixture-of-Experts (MoE，混合专家) 控制 active compute，31B Dense 面向更高能力密度。

### 2. 已有解决方案与不足

Gemma 3 / 3n 已经覆盖 open-weight、多模态和 on-device 方向，但 Gemma 4 报告认为三类需求仍然突出：

1. 长上下文能力需要更低 KV cache 成本。常规 full attention 在 $128\mathrm{K}$ / $256\mathrm{K}$ context 下会让 KV memory 成为主要限制。
2. 多模态路径需要减少 encoder 和 LLM 之间的系统复杂度。独立 vision / audio encoder 带来参数、memory fragmentation 和 latency 成本。
3. 生成吞吐需要和模型一起设计。speculative decoding 常作为外部 serving 技术出现，Gemma 4 选择把 MTP drafter 随模型族一起训练和发布。

因此 Gemma 4 的设计重点从单纯扩大参数量推进到 serving path 共同设计：architecture、attention pattern、quantization、drafting head 和 modality ingestion 都成为同一条推理路径上的变量。

### 3. 作者可能的思考路径

可以重建作者的思路：

1. open-weight adoption 的瓶颈来自“特定硬件上能不能跑”，所以先按设备层级划分模型族。
2. 对 E2B / E4B，权重、KV cache、audio encoder 和 vision encoder 都需要极限压缩；对 26B / 31B，关键是把能力推高，同时保持 workstation 级部署可能。
3. 长上下文的高成本来自 global attention 层 KV cache，先通过 local / global attention interleaving 缩小 full attention 层数，再通过 unified K/V 和 p-RoPE 降低 global 层 cache。
4. decoding 的高成本来自目标模型逐 token 前向；若 MTP drafter 能复用主模型 hidden state 和 KV cache，就能把 speculative decoding 内置成模型能力。
5. 多模态的系统复杂度来自专用 encoder；12B Unified 选择从 raw image patch 和 raw audio chunk 直接投影到 LLM embedding space，验证 encoder-free 路径能否成立。

### 4. 核心假设或切入点

论文的核心假设有四条：

1. 每个规模点都应追求同等部署级别的 frontier performance，小模型也需要围绕自身部署约束重新设计。
2. long-context memory 可以通过 local / global attention、unified K/V 和 p-RoPE 组合降低，同时保持 retrieval 和 reasoning 指标。
3. MTP drafter 若复用主模型 activations 与 KV cache，可以减少额外 prefill，并支持可变 draft length。
4. encoder-free 多模态路径可以减少中等模型的系统复杂度，尤其适合 12B 这类希望在消费级硬件上部署的模型。

### 5. 方法 / 系统 / 理论框架

#### 模型族与参数布局

Gemma 4 公开五个主要规模点：

| Model | Architecture | Context | Modalities | 关键部署定位 |
| --- | --- | --- | --- | --- |
| E2B | dense，$2.3\mathrm{B}$ effective / $5.1\mathrm{B}$ with embeddings | $128\mathrm{K}$ | text, image, audio | mobile / edge |
| E4B | dense，$4.5\mathrm{B}$ effective / $8\mathrm{B}$ with embeddings | $128\mathrm{K}$ | text, image, audio | laptop / local device |
| 12B Unified | dense，$11.95\mathrm{B}$ | $256\mathrm{K}$ | text, image, audio | encoder-free multimodal |
| 26B-A4B | MoE，约 $26\mathrm{B}$ total / $3.8\mathrm{B}$ active | $256\mathrm{K}$ | text, image | workstation / efficient large model |
| 31B Dense | dense，$30.7\mathrm{B}$ | $256\mathrm{K}$ | text, image | higher capability dense model |

26B-A4B 的 MoE 层包含 128 个 routed experts 和 1 个 shared expert，每个 token 激活 8 个 routed experts。这个设计让模型保持较大 total capacity，同时把每 token active compute 控制在约 $4\mathrm{B}$ 参数级别。

#### 长上下文 memory path

Gemma 4 采用 hybrid attention：local sliding-window attention 和 full global attention 交错，最后一层保持 global。E2B 的 local / global 比例是 $4:1$，其余模型是 $5:1$。local 层只看有限窗口，global 层负责跨文档整合。

朴素 global attention 会为每个历史 token 存储 key 和 value：

$$
\mathrm{KVCache}_{\mathrm{global}}=\{K_{1:T},V_{1:T}\}
$$

Gemma 4 在多数模型的 global attention 层采用 unified K/V，即让 value 直接复用 key：

$$
V_{1:T}=K_{1:T}
$$

这样 global 层 cache 中可以少存一份 value tensor。论文报告这种设计让 global KV cache 降低 $37.5\%$。成立条件是 global attention 层的 value 表达也使用 key projection 结果，模型需要在 pretraining 中适应这种表示约束；它属于训练期架构约束，不能作为推理期后处理压缩理解。

位置编码方面，local 层使用普通 RoPE，global 层使用 p-RoPE，其中 $p=0.25$。可以理解为只对部分维度施加旋转位置编码，给 global 层保留更多不随位置强旋转的通道。论文设置 global RoPE frequency 为 $1\mathrm{M}$，local RoPE frequency 为 $10\mathrm{k}$。

#### 多模态路径

E2B / E4B 使用约 $150\mathrm{M}$ 参数 vision encoder，26B-A4B / 31B 使用约 $550\mathrm{M}$ 参数 vision encoder。vision path 支持可变 aspect ratio 和 variable resolution，最大 token 数覆盖 70、140、280、560、1120 档位。

E2B / E4B 的 audio encoder 是 $305\mathrm{M}$ 参数 USM-based encoder，输入为 40ms Mel filterbank chunks，包含 2 个 downsampling convolution layers 和 12 个 Conformer layers。论文称相比 Gemma 3n 的 $680\mathrm{M}$ audio encoder，参数降低约 $55\%$。

12B Unified 选择另一条路径：它不使用单独 vision / audio encoder。图像被切成 $48\times 48\times 3$ RGB patches，经约 $35\mathrm{M}$ 参数 projection 进入 LLM embedding space；音频按 16kHz raw waveform 的 40ms chunk 切成 640 维向量，再投影到 embedding space。这个路线减少专用 encoder 和跨模块部署复杂度，但论文只在 12B 规模验证。

#### Quantization-Aware Training

Gemma 4 对权重、activation、vision encoder 和 audio encoder 都做 QAT。官方表格给出 text-only 权重和 int8 KV cache 的内存 footprint：

| Model | bf16 weights | Quantized weights | KV at 32k |
| --- | ---: | ---: | ---: |
| E2B | 4.6 GB | 0.8 GB mobile | +0.05 GB |
| E4B | 9.0 GB | 2.3 GB mobile | +0.14 GB |
| 12B | 24.0 GB | 7.65 GB Q4_0 | +0.28 GB |
| 26B-A4B | 52.0 GB / 7.6 GB active | 16.2 GB / 2.8 GB active Q4_0 | +0.28 GB |
| 31B | 64.0 GB | 19.2 GB Q4_0 | +1.10 GB |

vision encoder 的 W8A8 path 将 forward-pass memory 从约 400MB 降到 200MB，并在较新硬件上相对 Gemma 3n 降低 $44\%$ latency。audio encoder 采用 activation int8 和按 layer cluster 选择的 2/4/8-bit weight quantization，on-disk footprint 从 390MB 降到 87MB。

#### Multi-Token Prediction drafter

Gemma 4 将 MTP drafter 作为模型族的一部分发布，用于 speculative decoding。MTP (Multi-Token Prediction，多 token 预测) 的目标是在目标模型完成当前 token 后，额外预测若干未来 token，再由目标模型验证，从而减少逐 token decode 的串行等待。

![Figure 1: Gemma 4 autoregressive MTP drafter architecture](/images/papers/2607.02770-gemma-4-technical-report/fig-1-mtp-drafter.png)

Figure 1: 自回归 MTP drafter 由主模型 hidden state 和 KV cache 条件化，蓝色 drafter block 预测未来 token，并把每一步结果继续作为后续 draft 输入。Image Source: [arXiv HTML x1.png](https://arxiv.org/html/2607.02770/x1.png).

朴素 MTP head 常见问题是需要额外 prefill 或只能输出固定位置的未来 token。Gemma 4 的 drafter 采用小型 autoregressive Transformer block：主模型在当前步输出 token 后，drafter 读取主模型最后一层 activation、token embedding 和主模型 KV cache；drafter 自身有独立 embedder / unembedder，并用 4-layer Transformer cross-attend 到主模型 KV。这样 draft token 可以顺序生成，draft length 可以在服务端按需要调整。

对于 E2B / E4B，论文还优化了 final vocabulary projection。朴素路径需要计算：

$$
H_{\mathrm{draft}}\in\mathbb{R}^{d},\quad W_{\mathrm{vocab}}\in\mathbb{R}^{d\times 262{,}000}
$$

每步都要做 $d\times 262{,}000$ 的 projection。Gemma 4 把词表分 cluster 后先做 top-k cluster selection，再只对候选 cluster 内 token 做最后矩阵乘，报告称主要矩阵乘可降到约 $d\times 4{,}096$，同时保持相近 acceptance rate。这是 top-k 的分块思想：先在较粗粒度上筛掉大部分词表块，再在少量块内做精细 token ranking。成立条件是 cluster classifier 能把目标 token 所在词表块放进 top-k，否则 draft quality 和 speculative acceptance 会下降。

#### 训练与基础设施

pretraining 数据覆盖 web、code、image、audio 等来源，知识 cutoff 是 2025-01。tokenizer 继续采用 Gemini 系列 SentencePiece tokenizer，词表大小 262k，保留 digit splitting、whitespace preservation 和 byte-level fallback。

训练基础设施采用 TPUv5p / TPUv6e、JAX、Pathways、GSPMD、MegaScale XLA 和 ZeRO-3 optimizer state sharding。论文披露的芯片规模如下：

| Model | TPU | Chips | Sharding summary |
| --- | --- | ---: | --- |
| E2B | v6e | 4096 | Data 16 / Sequence 8 / Replica 32 |
| E4B | v6e | 6144 | Data 16 / Sequence 16 / Replica 24 |
| 12B | v5p | 12288 | Data 16 / Sequence 16 / Replica 48 |
| 26B-A4B | v6e | 6144 | Data 16 / Sequence 16 / Replica 24 |
| 31B | v6e | 10240 | Data 16 / Sequence 16 / Replica 40 |

更大模型使用 Slice-Granularity Elasticity，在局部 TPU slice 故障后允许训练以较少 slice 继续运行，把 interruption delay 从分钟级降低到秒级。

### 6. 结论链条

Gemma 4 的结论链条可以概括为：

1. open-weight 模型族需要覆盖从移动端到 workstation 的硬件层级。
2. dense、MoE、hybrid attention、unified K/V、p-RoPE、QAT 和 MTP drafter 共同降低 long-context 与 decode 成本。
3. 12B Unified 显示 image / audio 可以通过 projection 进入 LLM embedding space，减少单独 encoder 依赖。
4. thinking mode 和 instruction tuning 让 Gemma 4 在 STEM、coding、long context、agentic 和 multimodal benchmark 上明显超过 Gemma 3 系列。
5. 官方 human evaluation 中，31B Dense 与部分更大 open 模型处于相近 Elo 区间，26B-A4B 以较低 active compute 提供接近能力。

## 关键实验/定理

### 结果 1：Arena Text 中 31B Dense 接近更大 open 模型

- 设置：论文报告 Arena Text human evaluation，截至 2026-06-19。
- Baseline：Claude Fable 5、GLM 5.1 / 5.2 Max、MiMo V2.5 Pro、Kimi K2.6、DeepSeek V4、Qwen 3.5 等。
- 指标：Arena Elo 和 rank，带置信区间。
- 结果：

| Model | Type | Rank | Elo |
| --- | --- | ---: | ---: |
| Claude Fable 5 | closed | 1 | $1508\pm 9$ |
| GLM 5.2 Max | closed | 25 | $1471\pm 10$ |
| DeepSeek V4 Pro Thinking | open | 36 | $1458\pm 5$ |
| Gemma 4 31B | open dense 31B | 43 | $1451\pm 8$ |
| Kimi K2.5 Thinking | open | 44 | $1450\pm 4$ |
| Qwen 3.5 397B-A17B | open | 57 | $1444\pm 4$ |
| Gemma 4 26B-A4B | open MoE | 61 | $1438\pm 8$ |
| Gemma 3 27B | open dense 27B | 157 | $1366\pm 4$ |

- 解读：31B Dense 的官方 human preference 表现和部分更大 open models 接近，且大幅高于 Gemma 3 27B。该结果证明 Gemma 4 在 human-rated response quality 上有显著代际提升；由于 Arena 版本、prompt 分布和外部模型状态会更新，横向排名需要按 2026-06-19 这一快照解读。

- 设置：除 Gemma 3 27B baseline 外，Gemma 4 表格默认使用 thinking model。
- Baseline：Gemma 3 27B non-thinking，以及 Gemma 4 各规模点。

- 结果：

| Benchmark | 31B | 26B-A4B | 12B | E4B | E2B | Gemma 3 27B |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| MMLU Pro | 85.2 | 82.6 | 77.2 | 69.4 | 60.0 | 67.6 |
| AIME 2026, no tools | 89.2 | 88.3 | 77.5 | 42.5 | 37.5 | 20.8 |
| LiveCodeBench v6 | 80.0 | 77.1 | 72.0 | 52.0 | 44.0 | 29.1 |
| Codeforces Elo | 2150 | 1718 | 1659 | 940 | 633 | 110 |

- 解读：31B / 26B-A4B 在数学和 coding 上接近，MoE 版本以较少 active 参数获得强结果；12B Unified 在 coding、Tau2 和 instruction following 上明显强于小模型。报告没有给出每个 benchmark 的采样温度、样本数、工具协议和统计显著性细节，因此更适合看作官方 capability map。

### 结果 3：long-context 指标和 memory 设计方向一致

- 设置：比较 Gemma 4 各规模与 Gemma 3 27B，在 RULER、LOFT、GraphWalks 和 MTOB 上评估长上下文。
- Baseline：Gemma 3 27B non-thinking。
- 指标：RULER score、LOFT Text Retrieval Recall@k、GraphWalks F1、MTOB chrF。
- 结果：

| Benchmark | 31B | 26B-A4B | 12B | E4B | E2B | Gemma 3 27B |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| RULER 32k | 96.8 | 97.3 | 96.4 | 95.2 | 83.0 | 91.1 |
| RULER 128k | 96.4 | 89.8 | 91.2 | 86.6 | 70.4 | 66.0 |
| LOFT Text Retrieval 128k | 79.5 | 66.3 | 66.4 | 58.5 | 50.5 | 8.6 |
| GraphWalks F1, <128k | 82.3 | 72.6 | 71.0 | 50.9 | 4.1 | 32.8 |
| MTOB eng->kgv, ~128k | 52.9 | 50.0 | 45.1 | 37.8 | 15.4 | 41.0 |

- 解读：Gemma 4 的 long-context metrics 和 hybrid attention / p-RoPE / unified K/V 设计目标一致。31B 最稳，26B-A4B 和 12B 在部分 retrieval / reasoning 任务上接近。E2B 在 RULER retrieval 上仍能跑到 $128\mathrm{K}$，但 GraphWalks 这类结构推理明显弱。

### 结果 4：vision 和 audio 结果支持 natively multimodal 定位

- 设置：vision benchmark 比较 Gemma 4 各规模与 Gemma 3 27B；audio benchmark 比较 Gemma 4 E2B/E4B 与 Gemma 3n，并单独报告 12B Unified。
- Baseline：Gemma 3 27B / Gemma 3n E2B/E4B。
- 指标：MMMU Pro、MATH-Vision、MedXPertQA MM、InfographicVQA、OmniDocBench、CoVoST、FLEURS。
- 结果：

| Vision benchmark | 31B | 26B-A4B | 12B | E4B | E2B | Gemma 3 27B |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| MMMU Pro | 76.9 | 73.8 | 69.1 | 52.6 | 44.2 | 49.7 |
| MATH-Vision | 85.6 | 82.4 | 79.7 | 59.5 | 52.4 | 46.0 |
| InfographicVQA | 92.0 | 89.3 | 88.4 | 70.0 | 63.9 | 70.6 |
| OmniDocBench 1.5, lower better | 0.131 | 0.149 | 0.164 | 0.181 | 0.290 | 0.365 |

audio 上，Gemma 4 E2B / E4B 相对 Gemma 3n 在 translation 任务上分别有 $12\%$ / $10\%$ 相对提升，在 transcription 任务上分别有 $17\%$ / $12\%$ 相对提升。12B Unified 在没有 dedicated audio encoder 的设定下仍给出 CoVoST 和 FLEURS 多语种结果，说明 raw audio projection 路线具备可行性。

- 解读：多模态能力是 Gemma 4 相对 Gemma 3 的主要提升之一。12B Unified 的意义更偏架构验证：它证明 encoder-free path 可以进入可用区间，但论文没有证明该路线在所有规模上优于专用 encoder。

### 结果 5：QAT 和 MTP 给出部署端效率路线，但端到端服务证据仍不完整

- 设置：QAT 结果来自模型卡 / 报告内存表；MTP 结果来自架构描述和 Efficient MTP Decoding 段落。
- Baseline：bf16 weights、full vocabulary projection、外部 speculative drafter。
- 指标：weight footprint、KV cache footprint、vision/audio encoder memory 与 latency、drafter projection size。
- 结果：E2B quantized text-only weights 为 0.8GB，E4B 为 2.3GB，31B Q4_0 为 19.2GB；audio encoder on-disk footprint 从 390MB 降到 87MB；E2B/E4B drafter 的 final projection 主矩阵乘从 $d\times 262{,}000$ 降到约 $d\times 4{,}096$。
- 解读：效率路线清楚：先通过 QAT 降低权重和 encoder footprint，再用 MTP drafter 降低 decode waiting time。缺口也清楚：报告没有给出端到端 serving throughput、tail latency、acceptance rate 分布和硬件 profile，因此无法单独根据报告判断生产收益大小。

## 证据链强度评估

强证据：

1. 模型族、参数布局、context length、modalities、quantization footprint 和发布节奏有 arXiv、model card、release notes 交叉支撑。
2. hybrid attention、unified K/V、p-RoPE、MTP drafter、12B encoder-free path 等架构选择在报告中有明确描述。
3. TPU chip count、sharding summary 和训练基础设施披露相对具体。

中等证据：

1. Arena Text 和官方 benchmark 能说明 Gemma 4 的代际提升，但横向外部模型比较依赖具体评测快照。
2. QAT footprint 和 encoder memory/latency 说明部署收益方向，真实用户 workload 下的吞吐收益仍需要复测。
3. 12B encoder-free path 的 benchmark 证明路线可行，暂时不能推出专用 encoder 已经没有价值。

需要谨慎的推论：

1. 论文没有完整披露 pretraining token budget、数据 mixture、SFT / RL data、reward model、KL / entropy / optimizer 等 post-training 细节。
2. MTP drafter 缺少 acceptance rate、speculative speedup、GPU / TPU / mobile 硬件上的端到端 benchmark。
3. safety 评测以高层总结为主，无法独立复查每类风险的 failure rate。
4. MoE 26B-A4B 与 dense 31B 的成本比较需要结合具体 serving batch、KV cache、expert routing 和硬件实现；论文表格只能说明 active parameters 和 benchmark 结果。

## 本地讨论补充

Gemma 4 在本地档案中的位置更接近“open-weight model + serving efficiency co-design”节点。它把 MTP drafter、QAT、long-context attention 和 multimodal ingestion 放在模型报告正文中，说明 2026 年的 open model 技术报告已经从单纯能力榜单转向部署路径说明。

对后续阅读最有价值的追问有四个：

1. MTP drafter 在 vLLM / SGLang / mobile runtime 中的真实 acceptance、speedup 和 tail latency。
2. unified K/V global layers 在不同 long-context task 上的 ablation，尤其是 retrieval、multi-hop reasoning 和 code repository comprehension。
3. 12B encoder-free path 能否扩展到 26B / 31B 或 MoE 规模。
4. thinking mode 的 post-training recipe 和 safety tradeoff 是否会在后续 Gemma report 或 blog 中披露。

## 主要启发

1. open-weight 模型报告需要把 serving economics 写进主线。Gemma 4 的 QAT footprint、KV cache design 和 MTP drafter 比单独 benchmark 更能解释部署价值。
2. speculative decoding 正在从外部 serving trick 变成模型接口的一部分。Gemma 4 和本地 [2606.12370 Bebop](/papers/2606.12370-bebop-mtp-rejection-sampling-rl-training/)、[2605.27255 PIPO](/papers/2605.27255-pipo-latent-multi-token-prediction/)、[2602.06036 DFlash](/papers/2602.06036-dflash-block-diffusion-speculative-decoding/) 都说明 drafter / verifier / target 之间的训练耦合越来越重要。
3. long-context 优化存在多条路线：DeepSeek / MiniMax / GLM 更强调 sparse attention 或 indexer，Gemma 4 选择 local / global attention、p-RoPE 和 unified K/V 这条较规整的架构路线。
4. 12B Unified 提供了多模态系统简化方向：对中等模型，减少独立 encoder 可能比继续堆专用模块更利于本地部署和 runtime 集成。

## 局限

1. 训练数据规模、数据配比、token budget、wall-clock、训练成本、optimizer、learning-rate schedule 和 ablation 不完整。
2. post-training / RL / thinking mode 的 recipe 高度概括，难以复现。
3. MTP drafter 缺少完整端到端 serving benchmark，特别是 acceptance rate、speedup、latency tail 和硬件亲和性。
4. 12B encoder-free path 只在一个规模点验证，无法判断它是否是通用多模态替代路线。
5. safety 章节没有按风险类别提供细粒度表格、误差线和 failure examples。
6. human evaluation 和外部模型比较依赖 2026-06-19 前后的 Arena / model snapshot，后续排名变化会影响横向叙事。
