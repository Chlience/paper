## 一句话结论

PIPO 把输入侧 latent compression 和输出侧 Multi-Token Prediction (MTP，多 token 预测) 统一成 pair-in / pair-out 解码接口：输入端把两个 token embedding 压成一个 latent slot，输出端每个 backbone step 生成一个 backbone token 和一个 MTP draft token，再用 On-Policy Distillation (OPD，在线策略蒸馏) 中已经计算出的 teacher/student 概率比训练轻量 confidence head 替代昂贵 verifier；它在 Qwen3.5-4B/9B 上用更少 slot 取得更高 pass@4 和最高 $2.64\times$ TTFT、$2.07\times$ TPOT speedup，但 confidence head 取代 full verifier 后，严格分布保持保证弱于经典 speculative decoding。

## 论文脉络

### 1. 研究问题、背景和价值

长 chain-of-thought reasoning 把推理成本集中到 autoregressive decoding。标准解码每个 forward step 只提交一个 token，并且每步都要依赖已有上下文和 KV cache。数学、代码和长上下文推理会生成数万 token，中间 token 的成本逐渐超过 prompt prefill，成为 reasoning model 服务和 RL rollout 的主要瓶颈。

已有加速路线大致从两侧入手。输出侧 speculative decoding / MTP 试图每次 forward 产生多个 token；输入侧 latent compression 试图让模型用更少 effective slots 表示已经产生或输入的 token。PIPO 的价值在于把这两件事放进同一个接口：若每步输入是 token pair 的 latent 表示，每步输出也自然可以是 token pair，那么长推理链的 prefill、KV cache 和 decode 步数都可以同时下降。

### 2. 已有解决方案与不足

输出侧路线中，经典 [speculative decoding](/papers/2211.17192-fast-inference-transformers-speculative-decoding/) 用 draft model 提出候选，再用 target model 按 $\min(1,p/q)$ 验证并残差校正。它的优点是保持 target 分布，代价是每个 speculative step 仍要跑 full target verifier。EAGLE / EAGLE-2 把 draft 放到 hidden feature space，并行验证 candidate tree，仍然保留 verifier forward。

MTP head 直接挂在 backbone 上，可以把 draft head 变成模型内置组件。问题是无 verification 时 draft token 错误会继续进入后续上下文，论文主表里的 MTP baseline pass@4 大幅下降。Bebop 选择保留 rejection sampling verifier，并用 Total Variation (TV，总变差距离) loss 训练 MTP heads，提高 RL rollout acceptance。

输入侧路线中，CoLaR、Coconut、Soft Thinking 等 CoLaR-like 方法把若干 token 的 reasoning state 压入 continuous latent space。它们的共同问题意识很直接：长 CoT 中很多 token 主要承担“把中间状态传给下一步”的作用，服务端仍要为这些 token 保留 KV cache、继续逐 token decode。若中间思考只服务于模型内部状态传递，更自然的接口是把一段离散 reasoning trace 映射成更高带宽的连续表示，再把该表示喂回模型。

- [Coconut](https://arxiv.org/abs/2412.06769) 把 LLM 最后一层 hidden state 直接作为下一步 input embedding，即 continuous thought。训练时先用普通 CoT warm up，再在多阶段 curriculum 中逐步把前若干自然语言推理步骤替换成 latent thoughts，并用 `<bot>` / `<eot>` 标记 latent mode。它的关键收益是中间状态可以在连续空间里保留多个潜在下一步，论文把这种现象解释为接近 BFS 的隐式搜索；边界是 latent thought 的长度通常由阶段和超参设定，最终答案仍通过普通 language head 逐 token 生成。
- [Soft Thinking](https://arxiv.org/abs/2505.15778) 更像 inference-time 的 soft-token 机制：每个 thinking step 保留 vocabulary distribution，把所有 token embedding 按概率加权求和，得到 concept token，再把这个连续 embedding 注入下一步。它缓解了每步采样一个 hard token 带来的早提交问题，也通过 Cold Stop 用熵判断提前结束；边界是仅中间 thinking phase 使用连续 concept token，answer phase 仍回到离散 token 采样，且 serving stack 需要支持 soft embedding 输入。
- [CoLaR](https://arxiv.org/abs/2505.16552) 与 PIPO 的关系最近。它先随机采样 compression factor，把连续 reasoning token embedding 合并成 compressed embeddings；SFT 中同时让 language head 预测被压缩组内 token，让 latent head 预测下一段 compressed embedding。推理时 latent head 自回归地产生 compressed latent，prompt 可指定压缩因子；后续 RL/GRPO 利用概率 latent head 探索多条 latent reasoning path，并用短而正确的轨迹获得更高回报。PIPO 对 CoLaR 的批评点来自这里：CoLaR 需要直接预测下一段 latent embedding，并通常用高斯/soft-MSE/NLL 形式建模这个连续目标，而 multi-token continuation 天然更接近多峰离散分布，连续 latent regression 的分布假设会限制稳定性。
- [SoftCoT](https://arxiv.org/abs/2502.12134) / [Multiplex Thinking](https://arxiv.org/abs/2601.08808) 这类后续 soft-reasoning 变体也沿着同一方向扩展：SoftCoT 用轻量 assistant 一次性生成 soft thought tokens，再经 projection module 映射到主 LLM 表示空间；Multiplex Thinking 在每步采样 $K$ 个候选 token 并聚合成一个 multiplex token，让单个连续输入 slot 同时携带多条候选分支。

所以，这一组方法的共同收益是压缩或软化“已经想过的内容”：KV cache 和后续 attention 面对的是更短、更稠密的 latent/history。共同边界也一致：它们主要改造输入侧或中间思考状态，输出侧仍以一个 step 一个 token 为主，或者需要直接在连续空间预测下一 latent。PIPO 的切入点是：输入端压缩和输出端展开具有对称结构，可以用 pair interface 同时覆盖。

### 3. 作者可能的思考路径

可以重建出一条顺承的思路：

1. 长 CoT 的成本来自两部分：已生成 token 增加了 prefill / KV 负担，后续 token 仍需串行解码。
2. latent compressor 能压短上下文，MTP head 能减少解码步数；两者分别处理输入侧和输出侧。
3. 若 compressor 每次折叠两个 token，MTP head 每次展开一个额外 token，则模型内部的运行单位可以从 token 改成 pair。
4. MTP draft 仍需要可靠性判断。逐步 verifier 会抵消部分输出侧收益。
5. OPD 训练中已经需要拿 teacher 和 student 在同一 token 上的概率，speculative decoding 的接受概率也正好需要 teacher / draft probability ratio。
6. 于是可以把 verifier 的判断迁移为训练信号：训练时由 teacher/student ratio 监督 confidence head，推理时只跑小 MLP 判断 draft 是否接收。

### 4. 核心假设或切入点

PIPO 的核心假设有三条：

1. 相邻两个 token embedding 可以被一个小 MLP compressor 映射为 backbone 能消费的 latent slot。
2. 现代强模型内置 MTP head，pair-out path 可以利用已有模块，新增参数主要集中在 compressor 和 confidence head。
3. OPD 的 teacher/student 概率比可以给 confidence head 提供接近 speculative acceptance 的 supervision，从而把 recurring verifier cost amortize 到训练阶段。

### 5. 方法 / 系统 / 理论框架

#### 5.1 Pair-level decoding interface

PIPO 把 decode unit 从单 token 改为 token pair。第 $i$ 个 pair step 接收一个 latent input $z^i$，它表示原序列中的两个 embedding $(x^{2i}, x^{2i+1})$；模型输出 backbone-token distribution $p_b^{2i+2}$、draft-token distribution $p_d^{2i+3}$ 和 confidence score $c^i$。

若 $c^i\ge \tau_c$，draft token 被接收，下一步 pair 是 $(x^{2i+2},x^{2i+3})$。若 $c^i<\tau_c$，draft token 被拒绝，下一步 pair 变成 $(x^{2i+2},x^{\mathrm{pad}})$。PAD 保证接口仍保持 pair shape，使模型可以退回近似单 token decoding。

![PIPO architecture, SFT training, and OPD training flow](/images/papers/2605.27255-pipo-latent-multi-token-prediction/fig-3-pipo-training-flow.png)

Figure 3: PIPO architecture、SFT training process 与 OPD training process 的示意图。Image Source: [arXiv HTML x3.png](https://arxiv.org/html/2605.27255v2/x3.png).

#### 5.2 Pair-in compression

Compressor 把两个连续 token embedding 拼接后映射回 hidden size：

$$
z^i=f_{\theta}([x^{2i};x^{2i+1}]).
$$

默认 $f_\theta$ 是 MLP：

$$
f_\theta([a;b])=W_2\,\mathrm{SiLU}(W_1[a;b]).
$$

它初始化为近似 $a+b$，目的是让 backbone 一开始看到的输入分布接近预训练时 token embedding 的加法几何。附录 probe 显示，训练后的 compressor 仍保留 additive geometry，但学到 position-aware projection：first-input sensitivity share 均值约 $0.491$，swap-test cosine 均值约 $0.68$，输出与 $x^{2i}+x^{2i+1}$ 的 cosine 均值约 $0.65$ 且 norm 被压到约 $0.50$。

#### 5.3 Pair-out prediction

Backbone 在 compressed prefix 上产生 hidden state 和 backbone token distribution：

$$
h_b^i=\mathrm{Backbone}(z^{\le i}),
$$

$$
p_b^{2i+2}=\mathrm{LMHead}(h_b^i).
$$

MTP head 再利用 backbone hidden state 和刚生成的 backbone token embedding：

$$
h_d^i=\mathrm{MTPHead}(h_b^i,x^{2i+2}),
$$

$$
p_d^{2i+3}=\mathrm{LMHead}(h_d^i).
$$

附录给出的 MTP head 是最后一层之后的 full-attention decoder layer：

$$
h_d^i=\mathrm{Layer}\left(W_{\mathrm{fc}}[\mathrm{RMSNorm}(h_b^i);\mathrm{RMSNorm}(x^{2i+2})]\right).
$$

LM head 与 input embedding tied 并冻结；训练主要通过 LoRA 适配 backbone/MTP projection，以及全量训练 compressor、MTP projection/norm 和 confidence head。

#### 5.4 Confidence-guided draft acceptance

Confidence head 接收 backbone 与 MTP hidden state 拼接：

$$
c^i=g_\phi([h_b^i;h_d^i]).
$$

附录具体写成：

$$
c^i=\sigma\left(W_2\,\mathrm{SiLU}(W_1\,\mathrm{RMSNorm}([h_b^i;h_d^i]))\right).
$$

在 4B backbone 上，它约增加 $6.6$M 参数，约为 $0.16\%$。与 verifier 的 full backbone forward 相比，这个 MLP 的开销很小。

#### 5.5 SFT objective

Supervised Fine-Tuning (SFT，监督微调) 阶段训练 next-pair prediction。每个 pair step 同时预测 ground-truth backbone token 和 draft token：

$$
\mathcal{L}_{\mathrm{tok}}
=\mathrm{CE}(p_b^{2i+2},x^{2i+2})
+\mathrm{CE}(p_d^{2i+3},x^{2i+3}).
$$

Confidence head 在 SFT 阶段用 draft position gold token probability 做 bootstrap：

$$
\mathcal{L}_{\mathrm{conf}}^{\mathrm{SFT}}
=\mathrm{BCE}(c^i,p_d^{2i+3}(x^{2i+3})).
$$

总目标为：

$$
\mathcal{L}_{\mathrm{SFT}}
=\mathcal{L}_{\mathrm{tok}}
+\lambda_{\mathrm{conf}}\mathcal{L}_{\mathrm{conf}}^{\mathrm{SFT}}.
$$

训练时还随机把 draft-position input 替换为 $x^{\mathrm{pad}}$，让模型提前见到 rejected-draft 情况。实现中 $\rho\sim\mathrm{Uniform}(0,\rho_{\max})$，$\rho_{\max}=0.25$。

#### 5.6 OPD objective and verifier-as-teacher

OPD 阶段先让 PIPO 用当前 pair-level policy rollout，记录 accepted draft、rejected draft 的 PAD、student distributions $p_s$ 和 confidence scores $c$。之后移除 PAD，把干净文本交给未压缩 teacher，得到 token-level teacher distributions $p_t$，再把 teacher logprob 映射回 PAD-augmented positions。

主蒸馏损失是 reverse KL：

$$
\mathcal{L}_{\mathrm{distill}}=\mathrm{KL}(p_s\Vert p_t).
$$

实现中默认用 on-policy sampled token 的 Monte-Carlo reverse KL：

$$
\mathcal{L}_{\mathrm{distill}}
=\mathbb{E}_{y\sim p_s}\left[\log p_s(y)-\log p_t(y)\right].
$$

Speculative decoding 对某个 draft token $x$ 的接受概率是：

$$
\alpha(x)=\min\left(\frac{p_t(x)}{p_s(x)},1\right).
$$

PIPO 将同一个量作为 confidence target：

$$
y_c=\min\left(\frac{p_t(x)}{p_s(x)},1\right),
$$

$$
\mathcal{L}_{\mathrm{conf}}^{\mathrm{OPD}}
=\mathrm{BCE}(c,y_c).
$$

总 OPD 目标为：

$$
\mathcal{L}_{\mathrm{OPD}}
=\mathcal{L}_{\mathrm{distill}}
+\lambda_{\mathrm{conf}}\mathcal{L}_{\mathrm{conf}}^{\mathrm{OPD}}.
$$

这里关键省掉的是 inference-time verifier forward。经典 speculative decoding 在每次 draft 后都要运行 target model 验证；PIPO 在训练时已经计算 $p_t$ 与 $p_s$，因此把 acceptance ratio 变成 one-time supervision。推理阶段只用 confidence head 决定 accept / PAD fallback。

### 6. 结论链条

1. 长 CoT inference 同时受 effective input length 和 per-step output rate 限制。
2. Latent compression 处理输入侧，MTP 处理输出侧，两者可以用 pair-in / pair-out 对称接口统一。
3. Pair-in compressor 将两个 token embedding 合成一个 latent slot，pair-out MTP head 每步额外生成一个 draft token。
4. Draft token 的可靠性由 confidence head 判断，拒绝时用 PAD 保持 pair interface。
5. OPD 本来就要计算 teacher/student token probabilities，这些概率能直接构造 speculative acceptance target。
6. 推理时 confidence head 替代 verifier forward，减少 recurring verification cost。
7. 在固定 32K slot budget 下，PIPO 既能节省 slot，又能让同样 slot 容纳更多 reasoning content，因此 pass@4 与 latency 同时改善。

## 关键实验/定理

### 结果 1：PIPO+OPD 是主表中最强 pass@4 方法

- 设置：Qwen3.5-4B / 9B backbone；AIME 2025、GPQA-Diamond、LiveCodeBench v6、LongBench v2 short；temperature $1.0$，top-p $0.95$，top-k $20$，repetition penalty $1.5$；每题采样 4 条；32K slot response budget。
- Baseline：Regular decoding、MTP without verification、EAGLE-2、PIPO-SFT。
- 指标：avg@4 与 pass@4。
- 结果：

| Backbone | Method | Overall avg@4 | Overall pass@4 | AIME pass@4 | LiveCodeBench pass@4 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3.5-4B | Regular | 52.16 | 63.48 | 63.33 | 44.27 |
| Qwen3.5-4B | EAGLE-2 | 46.21 | 60.26 | 60.00 | 43.51 |
| Qwen3.5-4B | MTP | 38.50 | 52.28 | 43.33 | 27.48 |
| Qwen3.5-4B | PIPO-SFT | 45.28 | 65.01 | 60.00 | 48.85 |
| Qwen3.5-4B | PIPO+OPD | 46.52 | 67.31 | 76.67 | 49.62 |
| Qwen3.5-9B | Regular | 57.67 | 68.03 | 66.67 | 54.20 |
| Qwen3.5-9B | EAGLE-2 | 53.09 | 63.43 | 63.33 | 45.80 |
| Qwen3.5-9B | MTP | 41.61 | 56.10 | 50.00 | 31.30 |
| Qwen3.5-9B | PIPO-SFT | 51.18 | 71.58 | 76.67 | 54.20 |
| Qwen3.5-9B | PIPO+OPD | 57.34 | 75.18 | 83.33 | 62.60 |

- 解读：PIPO+OPD 相对 Regular 的 overall pass@4 提升为 $+3.83$ pp (4B) 与 $+7.15$ pp (9B)。PIPO-SFT 牺牲部分 avg@4 换取 pass@4，OPD 主要恢复稳定性：9B 上 avg@4 从 $51.18$ 升到 $57.34$，同时 pass@4 从 $71.58$ 升到 $75.18$。

### 结果 2：pair-in / pair-out 带来 TTFT 与 TPOT speedup

- 设置：HuggingFace backend；Qwen3.5-4B；input lengths $\{2,4,8,16,32,64,128\}$K；16 次 trial 平均；TPOT 取前 16 个 generated tokens。
- Baseline：Regular、MTP。
- 指标：Time-to-first-token (TTFT，首 token 延迟)、Time per output token (TPOT，单输出 token 平均延迟)、output slots。
- 结果：

| 维度 | 关键数字 |
| --- | --- |
| TTFT | Regular 从 $0.139$s (2K) 增至 $20.3$s (128K)；PIPO 在 2K 为 $1.65\times$ speedup，在 128K 达到 $2.64\times$ speedup，$20.3$s 降到 $7.69$s。 |
| TPOT | PIPO 在 2K 达到 $2.07\times$ speedup，$26.3$ 降到 $12.7$；128K 为 $1.98\times$，$27.9$ 降到 $14.1$。 |
| Output slots, 4B | Regular $20{,}160$，EAGLE-2 $21{,}667$，MTP $22{,}072$，PIPO-SFT $18{,}082$，PIPO+OPD $19{,}431$。 |
| Output slots, 9B | Regular $19{,}140$，EAGLE-2 $20{,}584$，MTP $21{,}857$，PIPO-SFT $17{,}494$，PIPO+OPD $18{,}590$。 |

![PIPO efficiency summary across input lengths](/images/papers/2605.27255-pipo-latent-multi-token-prediction/fig-4-pipo-efficiency.png)

Figure 4: Qwen3.5-4B 在不同输入长度下的 TTFT 与 TPOT，结果取 $16$ 次 trial 的平均值。Image Source: [arXiv HTML x4.png](https://arxiv.org/html/2605.27255v2/x4.png).

- 解读：TTFT 收益主要来自 pair-in compression 把 effective prefill length 减半；TPOT 收益来自一次 backbone forward 提交两个 token 的 pair-out path。PIPO+OPD 相对 Regular 还用更少 output slots，说明 pass@4 提升并非单纯来自更长生成。

### 结果 3：compressor 的非线性和初始化影响很大

- 设置：Qwen3.5-4B；PIPO-SFT architecture / training data ablation；四个 benchmark overall。
- Baseline：default PIPO-SFT。
- 指标：overall avg@4 / pass@4。
- 结果：

| Variant | avg@4 | pass@4 |
| --- | ---: | ---: |
| PIPO-SFT default | 45.28 | 65.01 |
| Linear compressor | 43.86 | 60.38 |
| Shortest response only | 42.88 | 59.87 |
| Random compressor init | 38.74 | 57.73 |

- 解读：MLP compressor 比 linear compressor 高 $+4.63$ pass@4；$a+b$ 初始化比 random init 高 $+7.28$ pass@4。这说明 pair latent 对 backbone 输入分布很敏感，compressor 需要同时维持 embedding geometry 和学习 pair order。

### 结果 4：confidence head 的阈值存在 pass@4 sweet spot

- 设置：Qwen3.5-4B PIPO-SFT；扫 $\tau_c\in\{0,0.5,0.8,0.9,0.95,0.98,1.0\}$，并用 Random baseline 匹配平均 pad ratio。
- Baseline：同 pad ratio 的 random accept/reject；pad ratio $1$ 对应极保守单 token fallback。
- 指标：overall avg@4 / pass@4。
- 结果：confidence curve 在中间 pad ratio 全程优于 random；$\tau_c=0.95$、pad ratio $0.665$ 时 pass@4 达到 $65.01$，高于 pad ratio $1$ 的 $64.55$；pad ratio 约 $0.6$ 时，confidence pass@4 为 $61.93$，random 为 $59.64$。
- 解读：confidence head 不只是 acceptance-rate knob。它在相同接受预算下能保留更有价值的 draft，拒绝更容易污染后续上下文的 draft。

## 证据链强度评估

### 强证据

- 论文主表覆盖数学、科学问答、代码和长上下文四类 benchmark，并在 4B/9B 两个 backbone 上重复观察到 pass@4 提升。
- latency analysis 同时拆出 TTFT、TPOT 和 output slots，能区分输入压缩和输出多 token 预测两类收益来源。
- ablation 明确验证了 compressor 非线性、$a+b$ 初始化、多 correct trajectories 和 confidence threshold 的作用。
- 附录 probe 直接检查 compressor 与 PAD 的行为，支撑 pair-in interface 不会在 rejected draft 时严重污染 hidden state 的主张。

### 中等强度证据

- OPD 对 avg@4 的恢复在 9B 上非常明显，在 4B 上 avg@4 仍低于 Regular；这说明稳定性提升和模型尺度相关。
- PIPO+OPD 的 pass@4 高于 Regular，但 avg@4 在部分任务上仍低，适合强调 answer-space coverage 的场景。
- GitHub 提供代码、checkpoints、data download 与训练脚本，提高可复验性；仓库也公开列出当前工程限制。

### 需要谨慎的推论

- Confidence head 替代 full verifier 后，生成分布缺少经典 speculative decoding 的 exact correction proof；它更像 learned acceptance policy。
- 主表未覆盖 DFlash / DSpark / Bebop TV-trained MTP 这类 2026 年强 speculative 路线，不能直接推出 PIPO 优于整个 speculative decoding 家族。
- OPD 训练需要 teacher forward 和较高显存；仓库说明 OPD 约需 $130$GB/GPU，SFT 约 $75$GB/GPU，训练成本可能明显高于普通 LoRA SFT。
- Radix cache disabled 会影响真实 serving 中的 prefix reuse 收益，尤其是多请求共享 prompt 或 agentic harness 重复调用时。

## 本地讨论补充

### 1. 讨论收敛点

- 本轮归档将 PIPO 定位为 inference architecture + training signal reuse：它将 OPD teacher/student 概率从蒸馏监督扩展为 acceptance supervision。
- 与 Bebop 的核心差别在于，Bebop 保留 rejection sampling verifier 并直接优化 TV overlap；PIPO 用 confidence head 学习接受决策，推理时取消 verifier。

### 2. 修正后的理解

- PIPO 的速度收益来自双侧：pair-in 缩短 effective context，pair-out 减少 decode step。若只启用 MTP，无 verifier 或 confidence 会显著降低 pass@4。
- PIPO 的质量收益很大程度来自 fixed slot budget 下能容纳更多 reasoning content；在无限 response budget 或对 pass@1/avg@1 更敏感的应用中，需要重新评估。

### 3. 后续复验指标

- 在 DFlash / EAGLE-3 / Bebop TV-MTP / DSpark 风格 baselines 下复测 pass@4、avg@4、TTFT、TPOT。
- 检查 learned confidence acceptance 的 calibration、false accept rate、false reject rate 与 token-level safety drift。
- 在 agentic multi-turn server 中复测 radix cache disabled、PAD fallback、tool-call boundary 和 KV cache reuse 的交互。

## 主要启发

- OPD teacher/student logits 可以服务多个目标：除了 token-level distillation，也能监督 verifier-like acceptance head。
- 对长 CoT 系统，输入侧 compression 与输出侧 multi-token generation 可以组合，不必只在 decoder step 上做优化。
- Learned acceptance head 的部署成本很低，但它把 exact speculative guarantee 换成了 empirical confidence calibration，适合用 task-level quality/latency 指标评估。
- PAD fallback 是 pair-level decoder 的关键工程细节：拒绝 draft 后仍保持 shape，避免模型接口在单 token 与双 token 之间频繁切换。
- Slot budget 是理解 pass@4 提升的重要变量。PIPO 提升可能来自更高 token-per-slot 和更少 truncation，也来自 OPD 后 draft quality 改善。

## 局限

1. 只研究 pair-in / pair-out，即 compression factor 为 $2$；更大 compression factor 可能更快，也更难训练。
2. 实验只覆盖 4B-9B Qwen3.5，跨更大 MoE、不同 tokenizer、无原生 MTP 的模型仍需复验。
3. 任务集中在答案可验证的数学、代码、科学问答和长上下文选择题，未评估对话、创意写作和安全敏感生成。
4. 只覆盖 text-only model；多模态输入的 latent compression 需要 modality-specific compressor。
5. 公开实现有 radix cache、prefill draft、显存和 backbone 支持限制，production serving 还需要工程迭代。
