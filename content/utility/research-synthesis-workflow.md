# Research Synthesis Workflow

First-Archived-At: 2026-07-22 10:00
Updated-At: 2026-07-22 17:20

## 目标与触发条件

研究主线由用户对一个方向的明确总结、综述、进展梳理或时间线请求建立。一次请求直接产生一条正式主线；主线身份无需候选阶段和内容审阅。不同请求默认保持独立，不自动合并、拆分或改名。

主线文章是该方向的唯一事实来源，保存在 `content/mainlines/<slug>.md`，公开路径为 `/mainlines/<slug>/`。它独立于单篇论文档案：不进入 `/papers/`、`content/utility/papers-index.md`、`data/paper-tags.json`、论文数量或论文审阅队列。主线进入全局检索，并在所引用的本地论文页生成反向入口。

单篇论文、技术报告、模型卡、博客、既有发表综述和框架文档继续使用 [Paper Analysis Workflow](/workflow/) 与 [Paper Note Template](/template/)。用户要求跨材料回答一个方向性问题时使用本工作流与 [Research Mainline Template](/mainline-template/)。

## 主线身份与文章状态

主线身份来自用户请求，创建后立即成立。文章内容仍使用独立审阅状态：

- 新文章头部从 `Review-Status: pending` 开始。
- `pending`：文章已经形成，等待用户确认综合判断、边界、证据和局限。
- `approved`：用户已经确认文章内容，记录分钟精度的 `Reviewed-At`。
- `needs-review`：已审阅文章发生实质更新，保留上次 `Reviewed-At`。

身份和文章状态分开处理。`pending` 主线仍是正式主线；内容审阅不会决定主线是否存在。更新只在用户明确要求时执行。新增普通论文、标签变化和定时任务不会自动修改主线文章。

## Definition of Done

一条研究主线完成归档需要同时满足：

- 标题和 slug 不含时间窗，能够稳定承载后续更新。
- `Source` 声明问题、责任组织、检索服务、带截止分钟与时区的时间窗、主题专属分类轴和图片准入决定。
- `### 检索与纳入协议` 记录检索式、纳入条件、排除条件、版本口径和已知覆盖缺口。
- 正文使用独立综合结构，沿核心问题、分类框架、演进、跨材料比较和逐结论证据强度形成连续论证。
- 本地论文保留单篇直接证据；主线把材料归一到共同字段，并明确跨设置可比性。
- 所有本地论文链接有效；成员关系从文章链接产生，同一论文可以进入多条主线。
- 主线未进入论文索引、论文标签、论文计数和论文审阅筛选。
- 五项人工语义门禁、主线验证、论文验证、搜索测试、站点构建和页面 canary 均通过。
- 完整改动创建本地 commit；只有用户明确要求时 push。

## 一、建立稳定问题与时间窗

先写一个可以被材料支持、限定或推翻的问题。标题描述稳定方向，时间范围放在 `Search window`、演进脉络和更新记录中。例如标题使用“LLM 与 Agent 强化学习中的信用分配”，文章内部记录“2026-05-01 至 2026-07-22 17:20 CST”。

`Source` 固定声明：

- `Workflow version: synthesis-v1`
- `Material type: composite`
- `Analysis modules`：必须包含 `survey`，再按实际主张加入其它模块
- `Responsible organization`
- `Search services`
- `Search window: YYYY-MM-DD 至 YYYY-MM-DD HH:mm TZ`
- `Research question`
- `Classification axes`：使用分号分隔至少两个主题专属轴
- `Key figure decision: include|omit`
- `Key figure rationale`：使用 `omit` 时必填
- `Published / updated`、`Current version read`、`Accessed` 与 `Subjects`

`Source` 中的 `### 检索与纳入协议` 会提升到公开正文开头。协议记录实际使用的关键词和机制同义词、检索服务、正式来源回查、首次公开与版本更新口径、纳入条件、排除条件和覆盖缺口。候选数量只有在绑定具体查询和日期时才记录。

## 二、定义主题专属分类框架

每条主线拥有自己的分类框架，不继承全局 facet。分类轴必须直接服务核心问题，并允许不同材料落到同一组字段。

例如，RL 信用分配使用：

```text
信用单元 × 识别信号 × 分配算子 × 可比性条件 × 策略角色配置
```

可学习环境使用：

```text
环境角色 × 状态权威 × 转移权威 × 奖励权威 × 真实数据校准闭环
```

同名轴在不同主线中没有全局继承关系。新主线先从问题推导字段，再决定是否复用已有表达。分类框架发生变化属于实质更新，已审阅文章进入 `needs-review`。

## 三、管理材料与证据层级

主线可以纳入：

1. 已存档的单篇论文或技术材料，以 `/papers/<slug>/` 链接。
2. 未建立本地笔记的外部原始论文、官方项目、代码仓库、正式评审和数据集。
3. 现有综述作为检索核对或术语交叉验证材料。

外部材料无需为进入主线而先建立单篇笔记。关键结论优先依赖原始论文和官方来源。发表综述可以帮助发现材料或核对分类，不能替代它所概括的原始证据。

本地论文笔记负责保存公式、实验设置、作者关系、直接证据位置和单篇局限。主线负责将这些材料归一到共同字段，比较机制、证据条件与结论边界。相同论文可以进入多个主线；文章中出现的本地论文链接就是成员声明，构建器据此生成论文页回链。

## 四、使用独立正文结构

主线文章固定使用以下二级章节，保持顺序：

1. `Source`
2. `综合判断`
3. `核心问题与边界`
4. `分类框架`
5. `演进脉络`
6. `跨材料比较`
7. `证据强度`
8. `当前判断`
9. `开放问题`
10. `局限`
11. `更新记录`

`作者与关系`、`一句话结论`、`论文脉络`、`关键实验/定理`、`OpenReview / 审稿意见吸收` 和 `跨论文关系` 属于单篇论文结构，不进入主线强制章节。作者和机构事实保留在单篇笔记与 `data/authors.json`；主线只在解释组织路线或跨材料证据时引用必要事实。

写作从问题产生叙事顺序。时间线说明变化何时发生，比较表说明机制和条件如何不同，解释性段落连接原因、证据和后果。章节承担连续论证，避免把正文写成课程目录或逐篇摘要集合。

## 五、逐结论评估证据强度

证据强度绑定具体结论，不给整篇论文或整条主线一个统一等级。每个重要判断至少记录：

- 结论文本；
- 强度，例如强、中强、中、中弱、弱或待验证；
- 直接证据；
- 可比性和成立边界。

同一材料可以为“机制已实现”提供强证据，同时只为“跨任务通用”提供弱证据。正式发表提高来源稳定性，无法替代同设置对照、统计充分性、计算匹配和独立复验。

跨材料比较必须包含规范化表格。每行使用相同字段，至少覆盖机制、证据与主要边界。实验口径不一致时比较条件和最窄结论，不生成统一性能排名。涉及系统效率时，将 rollout、模型调用、训练计算、环境重放、GPU 时间、wall-clock 和硬件约束纳入成本。

## 六、更新、迁移与删除

用户明确要求更新某条主线时：

1. 保留原检索窗口和更新记录，追加新增区间与查询。
2. 核验材料版本、正式发表状态、撤稿和官方实现变化。
3. 更新分类表、演进脉络、逐结论证据强度和当前判断。
4. 新增或移除本地论文链接，使论文页回链随文章内容变化。
5. 更新 `Updated-At`；已审阅文章发生实质变化时设为 `needs-review`。

普通论文归档不会自动更新主线。用户要求合并、拆分、改名或删除主线时，先明确稳定路径、成员关系和旧 URL 处理方式；涉及删除或覆盖移动时遵守高危操作二次确认。旧主线 URL 默认不建立重定向，除非用户明确要求保留。

删除单篇论文时需要检查所有主线文章。如果主线仍依赖该材料，先修订论证和链接；主线结论因此变化时将文章设为 `needs-review`。删除主线不会删除其引用的单篇论文。

## 七、人工门禁与验证

提交前完成五项语义门禁：

1. **核心贡献对齐**：标题、研究问题、综合判断和当前判断指向同一方向。
2. **论证链完整**：分类框架、演进与比较能够回答研究问题。
3. **直接证据定位**：关键机制和结果连接原始材料或本地已审计笔记。
4. **最窄结论边界**：时间窗、版本、纳入范围、证据等级与跨设置可比性明确。
5. **局限与成立条件**：检索遗漏、代理信号、计算差异和未公开细节均有记录。
