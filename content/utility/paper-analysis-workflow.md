# Paper Analysis Workflow

First-Archived-At: 2026-06-19
Updated-At: 2026-09-05

## 目标与适用范围

阅读的交付物是一个可复查的判断：材料解决什么问题，区别性贡献如何工作，哪些证据支持哪些结论，以及判断会在什么条件下失效。阅读深度由用户问题和结论风险决定，篇幅由解释是否完整决定。

本 SOP 适用于单篇论文、技术报告、模型卡、已发表综述、博客和框架文档。当前归档契约为 `Workflow version: v3`，使用 [Paper Note Template](/template/)。用户明确提出方向综述、进展或时间线时，使用独立的 [Research Synthesis Workflow](/synthesis-workflow/) 和 [Research Mainline Template](/mainline-template/)。

## 执行入口

先在工作记录中确定阅读问题、交付方式、材料身份与版本。简单请求可以直接据上下文确定；只在歧义会改变分析对象、结论或写入范围时询问。

| 交付方式 | 触发与结果 |
| --- | --- |
| `analysis-only` | 分析、总结、解释或单篇比较：读取必要来源，直接回答；不修改仓库。局部问题只重建相关机制，整篇分析覆盖完整贡献与证据链。 |
| `archive-core` | 归档、建档、保存，或要求提交尚未归档的分析：完成核心阅读，写笔记、索引和标签，验证后本地提交。已有提交的 push 请求按 Git 规则处理。 |
| `enrichment` | 叠加的范围修饰项：用户点名，或未解的来源冲突、实现、审稿、身份问题会改变核心判断时补充对应证据。它不单独授予仓库写入权限。 |

阅读问题应能对应到具体答案，例如“收益来自结构变化还是额外计算”“定理适用于哪个训练对象”“系统在什么负载下加速”。未指定问题的整篇分析默认回答贡献、机制、证据与边界，不预设论文必有正面结果或可迁移启发。

## 阅读流程

### 1. 固定对象，建立主张地图

从规范来源确认标题、责任主体、版本和发布日期，检查本地是否已有同一材料。arXiv 以 abstract 页面确认身份，正文使用明确版本的 PDF、HTML 或 source；网页与仓库记录所读 release、tag、commit，无法固定时记录观察日期与限制。正文与附录、代码、模型卡版本不同，应逐项注明，不能拼成一个未存在过的版本。

先浏览摘要、引言中的贡献、方法总图、主要结果和局限，列出决定答案的主张。每条主张区分：

- **设计事实**：作者具体构造、定义或实现了什么。
- **观测或证明结果**：在哪些条件下测到或证明了什么。
- **作者解释**：作者如何归因、宣称新颖性或推广结果。
- **本地判断**：阅读者据此接受、收缩、质疑或外推什么。

这份地图可以是临时短列表，不要求新增公开章节或文件。每条关键主张先写清“需要什么证据才成立”，再定位证据。优先核验会改变一句话结论的主张；辅助贡献按其对首要贡献的作用展开。新颖性只比较实际核验过的工作；作者声称“首次”时保留归因。

### 2. 重建可复述的机制或论证

沿主张地图阅读所需正文与附录。对首要贡献，建立从输入或假设到输出、训练信号或定理结论的完整链条，解释各环节为什么存在。可执行方法写清关键状态、模型、数据和更新关系；理论写清定义、量词、假设、关键引理与结论的依赖；综述与文档写清纳入或行为规则如何产生最终判断。

同名对象先消歧：教师与学生、冻结与更新的策略、训练与推理版本、缓存中的标识与实际数据分别说明。区分训练时可用信息与部署时可用信息，检查目标泄漏、额外监督、oracle 条件和成本是否被带入比较。

机制解释包含两层：

1. **独立总览**：只读总览就能复述首要贡献、必要辅助贡献、完整链条、关键对象的角色和最终输出。
2. **必要详解**：读完相关详解就能进一步解释输入、核心操作、传递对象、设计理由与成立条件；可执行方法能走通一个最小实例，理论能说明关键推导依赖。未披露步骤就近标明。

归档时在 `论文脉络` 使用一个 `### 贡献与方法总览`。标题可以带编号，位置按理解顺序决定；简短方法可在该节完成详解，多阶段方法按需要增加同级或下级标题。旧式总览名称可兼容。背景、缺口和假设可以合并；作者实际披露的设计动机按来源解释，本地设计理由明确归因。不要求构造作者的心理过程、辅助贡献或固定数量的阶段。

关键公式前说明要计算、约束或证明什么，之后解释变量、维度或量词、信号方向、近似条件与实现后果。必要时给出可逐项对应定义的具体例子，并区分示意数值与论文实测。首要机制所需推导不能由模块名称或流程图替代；公式数量与标题层级不作为深度指标。

### 3. 检验主张，主动寻找收缩结论的证据

对每项决定核心结论的主张，在方法、结果、附录和作者明示局限中定位最直接证据，同时检查最可能改变解释的对照、消融、失败设置或反例。关键证据未读到时，返回来源补读或收缩判断。

每个关键结果围绕一项可判断的主张成文，保留四个可复查字段：

- `证据定位`：精确到版本内的章节、表、图、定理、页码，或固定版本的代码位置。外部材料用直接 URL；整篇首页只能定位来源身份。
- `观察`：来源实际报告的数值、关系、定理或行为，以及必要的设置、指标分母和比较对象。区分作者报告、本地计算、独立复现和示意例子。
- `判别性与局限`：该证据能区分哪些解释，尚不能排除什么；关键条件未披露时说明它会怎样影响判断。纯理论结果说明假设为何足以推导结论，哪些实践推论仍需证据。
- `支持的最窄结论`：把观察与解释联系起来，保留会改变真值的条件。证据不足或相互冲突也可以成为结论。

对照的价值取决于它改变和固定了什么。资源比较应区分参数量、激活参数、训练计算、推理计算、样本量、搜索或调参预算以及实际时间；未匹配的维度需要解释。统计结果检查独立实验单位、重复次数、误差范围、选择最佳运行和测试集参与选择的影响；来源未披露时记录缺口，不补算不存在的统计量。多指标、多个子集与平均数可能遮蔽失败条件，应读取与主张直接相关的分解结果。

机制构造正确、性能改善、原因得到识别和跨场景有效是不同主张。消融同时改动多个变量时，只能据其识别联合变化的效果；相关探针结果保留为机制线索。没有消融不自动否定工作，判断强度随可辨识程度调整。

条件检查按主张选用 `Analysis modules`，细则见 `internal/paper-analysis-modules.md`。模块决定检查问题，不要求搜齐所有超参数，也不按关键词判断科学质量。

### 4. 形成有边界的判断

将用户问题逐项对应到证据支持的答案，再写一句话结论。结论、索引核心信号与正文最深入部分指向同一首要贡献。使用可独立成立的自然语言，不使用公式或 TeX 数学定界符；数值必须附理解它所需的口径。重大负面结果、证据冲突或可验证性不足应进入结论。

局限按对判断的影响组织：哪项主张受影响、什么条件改变会失效、现有证据留下什么不确定性。已在关键结果中展开的限制，集中引用即可。不要把未披露、已证伪、未读取和无法访问写成同一种状态。

`主要启发` 可选。一个候选需要形成有证据来源的认识变化，例如修正设计判断、增加解释变量、限制定理的实践映射或识别失败条件；不能仅换词重述方法和数字。说明原有判断的可归因来源、触发变化的证据、新判断及成立边界。没有独立认识更新时省略本节，不预设数量或自然段配额。

迁移只在确有目标对象时展开：说明保留的抽象关系、目标实例化、可证伪预测和失效条件。缺少区分性证据的因果解释标为待验证假设，不能包装成稳定认识；有价值的局部判断不必人为配一个跨领域类比。每条启发有陈述新判断的标题和直接证据定位，细节可引用前文。

### 5. 按交付方式成文

`analysis-only` 先直接回答，再给理解答案所需的机制、证据与边界；局部请求不套整篇模板。只读任务中的临时主张地图、检查项和搜索过程不写入仓库。

`archive-core` 使用七个核心章节：`Source`、`一句话结论`、`论文脉络`、`关键实验/定理`、`局限`、`作者与关系`、`跨论文关系`。结果章可用兼容名称 `关键证据`、`关键实验结果`、`主要实验结果`、`关键定理`、`文献扫描结果` 或 `方法论论证`。章节顺序以科学问题和解释链为先；同一证据只在一个主要位置完整展开。

作者信息优先从作者块提取，保留顺序、论文时机构和明确贡献标记；不能映射到个人时记录机构集合。检查本地同名、别名及已有 profile，重复机构可以分组表达。普通作者只复用已有 profile；核心归档不新建或扩充作者 profile。外部作者信息按“指定作者 × 指定字段”启用 `enrichment`；完整作者关系或 profile 完善请求才扩展到作者顺序前两位、明确共同一作和通讯作者。代表论文只在请求包含该字段时写入 `representativePapers`，来源须为已核验主页明确选中的工作。

跨论文关系只记录实际核验且改变理解的联系，并区分引用关系、方法继承与本地比较。没有可靠关系时写“暂无高置信跨论文关系”。新发现先写当前笔记；旧笔记只因事实纠错、一句话结论真值变化或用户明确要求维护而回写。新论文不会自动更新主线。

关键图按解释价值决定：图能显著帮助理解机制、证据或失败边界时使用 `include`，并在首次讨论处嵌入带 `Image Source` 的本地图片；其余使用 `omit` 并说明理由。保留坐标、图例、条件和来源，用户要求的图片属于交付范围。

## 来源缺口、补充检索与停止条件

每次补充检索对应一个尚未解决的问题。优先读同版本正文与附录，再取直接相关的一手材料；摘要、转述或评审只能支持它们实际包含的信息。实现细节决定结论时可以只读代码；精确复现、环境安装、长时间计算或有外部副作用的执行，另按已授权范围处理。作者档案、社交账号与引用扩展均不能自动扩大阅读任务。

当用户问题已回答、关键机制可复述、核心判断有直接证据、主要替代解释与边界已处理，停止检索。来源数量、连续检索次数和没有新搜索结果都不能单独证明充分性。达到信息上限时分开交付：

| 状态 | 应对 |
| --- | --- |
| 原材料未披露 | 将缺口绑定到受影响主张，判断能收缩时给出有限结论。 |
| 关键材料尚未读到 | 继续读取，不把未读当作未披露。 |
| 来源不可访问 | 尝试可核验的官方替代；仍不可用时说明已读范围和未验证内容。 |
| 关键证据冲突 | 保留各自版本、设置和原始结果；不能解释时明确未解决，不合成平均结论。 |
| 缺口阻止回答 | 交付已确定部分并指出所需最小材料或决策，不宣称完成整篇分析。 |

用户明确要求保存不完整材料时可以按有限结论归档，在 `Reading scope` 与一句话结论中明确限制；只有摘要时不能写成已核验完整方法。默认归档仍需满足范围内的机制、证据与边界要求。

## Source 与审阅状态

必填来源字段为 `Workflow version: v3`、`Material type`、`Analysis modules`、`Canonical source`、`Title`、`Authors` 或 `Responsible organization`、公开日期、所读版本、`Accessed`、`Reading scope`、图片决定和公开审稿状态。材料类型与模块枚举见模板。`Reading scope` 用短句说明实际读过的正文、附录或代码范围，以及影响判断的未读或访问缺口；不宣称未执行的复现。

公开审稿与本地用户确认分别记录。公开状态不要求固定次数的搜索，按用户问题或可信度缺口决定是否检索：

```text
- Review status: page-type=not-checked; match-confidence=not-applicable; observed-at=YYYY-MM-DD; venue-status=unknown
```

| page-type | 含义与记录方式 |
| --- | --- |
| `not-checked` | 未核验外部评审；不能据此声称不存在评审。 |
| `not-found` | 实际检索未找到可靠匹配；补充 `Review lookup`，简记服务、查询与范围。结论限于本次检索。 |
| `unavailable` | 候选来源访问失败；`Review lookup` 记录目标与失败原因。 |
| `metadata-only` / `proceedings` / `commentary` | 分别只读元数据、正式出版记录或非正式评论；补充 `Review evidence` 定位对应 URL 与已读范围。 |
| `official-review` | 实际读到正式评审、meta-review 或 decision；增加审稿分析章，写明已读材料与直接定位、主要质疑、作者回应及对结论的影响。 |
| `not-applicable` | 材料不适用学术评审，注明材料身份。 |

`match-confidence` 表示候选材料与本文的身份匹配程度；有已读页面时用 `high`、`medium` 或 `low`，`not-checked`、`not-found`、`unavailable`、`not-applicable` 时用 `not-applicable`。`observed-at` 是状态记录日期，`venue-status` 只写来源支持的出版状态，未知写 `unknown`。状态不能证明内容正确。

审稿章的 `已读材料` 必须区分 decision、meta-review、选读 review 和 rebuttal。只读 decision 时不推断 reviewer 共识；未读回应写“未读取”，已读范围中没出现回应写“未在已读材料中披露”。是否继续读由质疑对核心判断的影响决定。

头部使用分钟精度的 `First-Archived-At`、`Updated-At`、`Review-Status: pending`。v3 允许同一分钟归档多篇，身份由 slug 区分，排序沿用 slug 决胜；时间如实记录。用户明确确认后改为 `approved` 并记录 `Reviewed-At`；后续修订保留原有 `Review-Status` 和 `Reviewed-At`。`approved` 表示曾获用户确认，不代表之后的每次修订都获确认。实质内容变化更新 `Updated-At`，纯排版、拼写和不改变来源身份的链接维护保留时间；审阅动作只更新审阅字段。

## 完成验收

主执行者在交付前完成一次科学自审；发现问题后只复查受影响部分。存在核心证据冲突、结论高风险或用户要求独立复核时，可启用独立审查者；范围限定到争议主张。结构检查通过不能替代以下人工验收：

1. **回答对齐**：答案回应用户问题；结论、证据与正文深度对齐首要贡献，负面结果没有遗漏。
2. **机制复述**：总览能独立复述完整链条，详解能走通关键操作或推导；对象、训练信号、条件与版本一致。
3. **证据判别**：核心主张对应实际观察或定理；明确比较口径和最强相关替代解释，未读与未披露分开。
4. **结论校准**：结论覆盖范围不超过证据；机制归因、外推与稳定认识均有对应依据，关键不确定性影响已说明。
5. **来源与范围**：来源和证据定位可复查，阅读缺口与实际启用的增强范围已交代；归档与用户审阅状态符合授权。

`archive-core` 还须通过模板结构、唯一索引行、标签、图片、链接和元数据完整性检查，审查暂存差异并创建本地 commit。索引使用 `简称 | 时间 | 核心信号`，按首次公开月份从新到旧排列；标签来自 `data/tag-taxonomy.json`，写入 `data/paper-tags.json`，一个主标签和最多三个辅助标签。

## 维护与兼容

阅读与科学判断的规范来源为本 SOP；模板只提供可填写骨架；条件分析细则归 `internal/paper-analysis-modules.md`；路径、标签、作者数据、公式图片、删除与验证细则归 `internal/paper-archive-maintenance-sop.md`。`AGENTS.md` 保存执行边界和路由，历史设计文档只记录决策背景。

新笔记使用 v3。既有 legacy、v2、v2.1 按冻结范围继续校验；v2.1 集合记录在 `internal/paper-workflow-v21-slugs.json`，只能随迁移缩减，不能加入新材料；验证器固定对应的 `Updated-At`，时间变化即要求迁移。旧笔记达到实质回写条件时迁移到 v3；单纯排版维护沿用原契约。原 `paper-workflow-method-overview-baseline.json` 只服务未迁移 v2.1 的兼容检查，迁移时移除对应记录。迁移保留来源事实、用户判断、首次归档时间与原审阅历史，不批量重写现有论文。

后续交流在取得归档授权后按语义进入当前笔记的机制、证据、局限、跨论文关系或主要启发，不新增 `本地讨论补充`。删除论文仍须精确路径的二次确认，并同步处理索引、标签、受影响关系、主线引用及无剩余论文关联的作者 profile；`orphan-author-profile` 为硬错误。

强制契约变更须在同次改动中对齐 `AGENTS.md`、SOP、模板、验证器、测试与至少一个新契约 fixture 或真实 canary。自动规则只检查可确定的结构和数据约束；新增语义要求提供人工验收问题与正反例，不用关键词数量代替。历史兼容测试继续运行，新增规则不能迫使无关笔记改写。

安全与双用途材料保留机制、风险、评测和防御启发，省略可直接滥用的操作细节；所省略内容影响理解时说明披露边界。
