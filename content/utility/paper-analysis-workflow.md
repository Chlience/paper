# Paper Analysis Workflow

First-Archived-At: 2026-06-19
Updated-At: 2026-08-25

## 目标

本工作流处理用户指定的单篇论文、技术报告、模型卡、博客或框架文档。交付模式由用户请求决定：只读分析直接返回结论，核心归档建立可追溯、可更新、可连接的长期笔记；增强范围按明确触发条件补充审稿、代码、作者或跨论文证据。

v2.1 使用固定质量底线和条件分析模块。每篇笔记都要说明研究问题、核心贡献、工作机制、直接证据和成立边界；实验、系统、理论、模型报告、综述、安全与文档类细节按材料实际主张启用。

`archive-core` 使用本工作流和 [Paper Note Template](/template/)；叠加 `enrichment` 时仍沿用同一 v2.1 结构。用户明确请求的跨论文时间窗、方法谱系或方向综合使用独立的 [Research Synthesis Workflow](/synthesis-workflow/) 与 [Research Mainline Template](/mainline-template/)。

## 交付模式与增强范围

单篇请求使用两种交付模式；模式属于当前任务的执行状态，不写入论文 `Source`：

| 模式 | 默认触发 | 交付范围 |
| --- | --- | --- |
| `analysis-only` | 分析、总结、解释、比较单篇材料 | 只读规范来源与回答问题所需的正文或附录，直接返回有证据边界的结论，不修改仓库 |
| `archive-core` | 归档、建档、保存、commit、push | 建立紧凑 v2.1 笔记，更新索引与标签，执行一次科学审计、验证和本地提交 |

`enrichment` 是范围修饰项，可以叠加在任一交付模式上。它只执行用户点名或会改变核心结论的审稿全文、代码复现、作者关系或账号、代表论文和完整跨论文维护；它本身不授予仓库写入权限。用户在 `analysis-only` 之后要求 commit 或 push 时，先完成 `archive-core`；已有可推送提交时直接按 Git 规则处理。

## 快速执行卡

两种交付模式先完成前三个阶段；实际启用的 `enrichment` 按需执行第 4 阶段。`analysis-only` 在请求范围完成后返回，`archive-core` 继续完成第 5、6 阶段：

1. **受理与分类**：唯一识别材料，确认交付模式、增强范围、材料版本、重复条目、分析模块和安全边界。
2. **核心证据**：读取规范来源及回答用户问题所需的正文或附录，定位关键章节、图表、定理或实验。`analysis-only` 采用规范来源明确显示的审稿状态；`archive-core` 最多增加一次标题或材料 ID 匹配，未找到即记录 `not-found`。
3. **问题与机制重建**：`analysis-only` 只重建回答当前问题所需的问题背景、局部机制、直接证据和成立边界；用户请求整篇分析时再覆盖首要贡献、核心假设和完整执行链或论证链。`archive-core` 补齐完整链条，证据已经覆盖归档要求及实际启用的增强范围后进入成文。
4. **条件可信度审计**：仅在用户明确要求、来源或版本冲突、实现细节决定结论，或审稿材料可能改变可信度时读取审稿全文、代码和历史版本。
5. **紧凑归档**：按七个核心章节成文，通常保留一至三个关键结果；候选通过稳定认识更新筛选时至多保留一条首要启发。更新索引与标签，关键图按不可替代的信息价值准入；作者档案和旧笔记回写按增强条件处理。
6. **一次科学审计与交付**：合并检查核心贡献、机制、直接证据、最窄边界和局限，运行本地验证，核对差异并创建独立本地 commit。

## 耗时检查点与停止规则

本轮修订使用最近一次完整归档工作轨迹（trace）的墙钟时间（wall-clock time）作为校准基线：

| 阶段 | 观测耗时 | 修订后的控制方式 |
| --- | ---: | --- |
| 核心证据与判断 | 27:53 | 约 20 分钟检查证据是否已覆盖问题，结论稳定后停止扩展来源 |
| 笔记生成 | 6:37 | 使用紧凑模板，通常保留一至三个结果；首要启发按候选筛选决定 |
| 集成与首次验证 | 5:00 | 保留一次 `check:source`，失败后只重跑受影响检查 |
| 终审与修订 | 10:54 | 合并为一次科学审计，修订后只复查受影响项 |
| 任务协调与交付 | 0:55 | 只保留三个关键时间点更新 |
| push | 0:47 | 保持现有 Git 路径，不作为主要优化对象 |

前五项构成 51:19 的归档主路径，push 在后续请求中耗时 0:47。同一工作轨迹中的作者增强分支耗时 33:40，主要与核心分析并行。该分支改为条件执行，以降低计算与协调成本；它不计入归档主路径耗时。

- 单篇任务在约 20 分钟停止没有结论增量的核心检索，在约 35 分钟冻结核心内容并进入最终验证。`archive-core` 独立交付；`enrichment` 不阻塞核心交付，并在约 60 分钟停止新增来源、保存已确认字段和报告未查明项。继续扩展由用户明确要求。检查点属于软预算，事实正确性、证据边界和兼容性仍是完成条件。
- 每次外部检索前先写明待解决的核心主张；没有明确主张时不检索。同一主张连续两个来源没有改变结论或边界时停止扩展。用户问题已经回答、首要贡献和边界已经稳定、每项核心主张都有一手证据时停止核心检索；未解决且不改变当前结论的问题写为“原因未查明”或“未查明”。
- 默认只设置一个证据分析分支，由主执行者完成一次合并科学自审。核心证据冲突、结论高风险或用户明确要求独立复核时再启用独立审查者。关键图准入由同一科学自审覆盖；只有作者或其它增强元数据实际修改时增加专项检查。
- 长任务通过 commentary 记录“核心证据锁定、草稿完成、验证完成”三个时间点，不新增仓库计时文件。

## `archive-core` Definition of Done

一篇材料完成核心归档需要同时满足以下条件；实际启用的 `enrichment` 另行满足对应 SOP：

- `Source` 声明 `Workflow version: v2.1`、材料类型和 `Analysis modules`，并包含可复查的来源快照。
- `Source` 声明 `Key figure decision: include` 或 `omit`；文字或表格足以解释核心结论时直接使用 `omit` 并写明理由，图片对机制理解具有不可替代作用或用户明确要求时使用 `include`，至少嵌入一张本地图片并标注 `Image Source`。
- 七个核心章节均有实质内容：`Source`、`作者与关系`、`一句话结论`、`论文脉络`、`关键实验/定理`、`局限`、`跨论文关系`。
- 候选通过稳定认识更新筛选时，`archive-core` 至多形成一条与首要贡献对齐的首要启发；没有独立认识更新时省略本节。实际保留的启发完成可归因的原有判断、论文专属的区分性证据、作用机制、抽象关系、迁移后的可证伪预测和失效边界；辅助启发属于用户明确要求的增强范围。
- `论文脉络` 清楚区分首要贡献与辅助贡献。包含多个关键阶段、角色、模型变体、训练分支或论证依赖的方法以 `### 5. 贡献全景与方法总览` 建立独立入口，单阶段方法使用 `### 5. 方法总览与完整机制`；只阅读第 5 节即可复述完整链条、关键对象及其角色差异，以及最终输出、训练信号或论证结论。多阶段方法至少展开首要机制，紧密耦合阶段可以合并说明；读完必要详解后可以进一步复述该机制的接口、训练信号或论证结果及其成立边界。
- `一句话结论`、索引核心信号和正文最深入部分指向同一项首要贡献；前两者只用自然语言描述，不使用公式或 TeX 数学定界符。
- 关键结果写明章节、公式、图、表、附录、页码、代码路径、commit 或 URL 证据定位，并给出证据支持的最窄结论。
- 已采用规范来源明示状态，并在需要时最多增加一次标题或材料 ID 匹配；未找到即记录 `not-found`。正式公开审稿存在时，以 decision、meta-review 和直接影响核心结论的质疑为主，紧凑记录认可、质疑、作者回应及其对可信度的影响。逐条 reviewer 梳理属于条件可信度审计。
- `Source` 与 `作者与关系` 保留论文作者块和论文时机构，并完成本地同名、别名和已有 profile 检查。核心归档不要求外部身份来源或新建 profile；实际启用作者 `enrichment` 时再按作者 SOP 保存稳定来源、代表论文和公开账号。
- 新论文记录当前来源直接支持且会改变理解的主题、引用或方法关系。普通关系只写新笔记；旧论文仅在新证据纠正事实错误、改变一句话结论真值，或用户明确要求跨论文维护时回写。
- `content/utility/papers-index.md` 保留唯一三列表格行；`data/paper-tags.json` 保留一个主标签和最多三个辅助标签。
- 笔记头部声明本地 `Review-Status`；新归档默认进入 `pending`，用户明确确认后进入 `approved`。后续修订更新 `Updated-At`，并保留原有审阅状态与审阅时间。
- 一次合并的科学审计覆盖五项人工语义门禁，本地内容工作流、元数据、公式、搜索和置顶检查通过；只有实际修改增强元数据时增加专项审计。
- 完整改动已创建本地 commit；推送只在用户明确要求后执行。

研究主线保存在 `content/mainlines/`，主线身份与内容契约见 [Research Synthesis Workflow](/synthesis-workflow/)。新增普通论文不会自动修改主线；论文被主线文章引用时，构建器会在论文页生成反向入口。

## Source 快照

新增笔记在 `Source` 中填写：

- `Workflow version: v2.1`
- `Material type`：`research-paper`、`technical-report`、`model-card`、`survey`、`blog` 或 `framework-docs`
- `Analysis modules`：从 `experiment`、`system`、`theory`、`model-report`、`survey`、`safety`、`docs` 中选择一个或多个
- `Canonical source`
- `Title`
- `Authors` 或 `Responsible organization` 至少一项
- `Published / updated`、`Submitted` 或 `Published` 至少一项
- `Current version read` 或 `Version / revision read` 至少一项
- `Accessed: YYYY-MM-DD`
- `Key figure decision`：`include` 或 `omit`
- `Key figure rationale`：仅在 `omit` 时必填，说明信息价值、版权、安全或材料形态原因
- `Review status`：使用固定键值记录 `page-type`、`match-confidence`、`observed-at` 和 `venue-status`

推荐格式：

```text
- Review status: page-type=not-found; match-confidence=high; observed-at=2026-07-17; venue-status=arXiv preprint
```

`page-type` 使用 `official-review`、`metadata-only`、`proceedings`、`commentary`、`not-found` 或 `not-applicable`；`match-confidence` 使用 `high`、`medium` 或 `low`。

arXiv 论文优先以 abstract 页面作为规范来源，并读取回答用户问题所需的 PDF、HTML、TeX source 或附录。代码、项目页和历史版本只在实现细节决定结论、材料出现冲突或用户明确要求时补充。网页、模型卡和框架文档优先使用责任主体发布的页面或仓库；只有版本影响结论时记录 release、tag 或 commit。单篇材料的规范来源使用官方绝对 URL。

每篇论文头部保留：

- `First-Archived-At: YYYY-MM-DD HH:mm`
- `Updated-At: YYYY-MM-DD HH:mm`
- `Review-Status: pending`

`Updated-At` 只在结论、证据、关系或其它实质内容变化时更新。

## 本地审阅状态

本地审阅状态记录用户是否已经完成过笔记内容确认，与 `Source -> Review status` 记录的公开 venue / peer-review 状态分别维护。`Reviewed-At` 保存用户明确确认的时间，后续修订不会改写这项历史。

- `Review-Status: pending`：分析已经归档，等待用户审阅。新增论文和缺少用户明确确认的历史论文使用该状态，不记录 `Reviewed-At`。
- `Review-Status: approved`：用户已经完成过核心贡献、直接证据、最窄结论边界和局限的确认，同时记录 `Reviewed-At: YYYY-MM-DD HH:mm`。后续修订仍使用 `approved`，保留该审阅时间，并允许 `Updated-At` 晚于 `Reviewed-At`。

内容、排版、错字和链接修订只更新 `Updated-At`，保留原有 `Review-Status` 和 `Reviewed-At`。论文目录通过 `/papers/?review=pending` 和 `/papers/?review=approved` 提供筛选深链；无查询参数时展示全部论文。

## 七个核心章节

### Source

保存来源身份、版本、日期、访问状态和外部核验结果。

### 作者与关系

核心归档按论文作者块保留姓名、顺序、论文时机构和通讯标记，并检查本地同名、别名和已有 profile。只有已核验且与理解论文直接相关时才补充历史机构、作者角色或关系；外部身份来源和新 profile 属于作者 `enrichment`。

### 一句话结论

用一段自然语言写明首要贡献、主要机制、最可靠证据和关键边界，不使用公式或 TeX 数学定界符。索引核心信号从本节提炼。

### 论文脉络

这是单篇笔记最重要的分析正文。按读者理解所需的因果顺序组织，无需沿用论文目录；先给出贡献全景，并明确首要贡献与辅助贡献。

在进入方法前依次回答：

1. 研究问题、背景和价值。
2. 已有方案与剩余缺口。
3. 作者可能的思考路径；推断明确标为本地分析。
4. 核心假设或切入点。
5. 核心贡献与方法、系统或理论框架。
6. 从假设到证据的结论链条。

方法详细度以形成解释闭环为准，不设统一字数。方法部分按实际执行顺序或理论依赖顺序展开，并遵守以下契约：

0. **建立独立总览入口**：方法包含多个关键阶段、角色、模型变体、训练分支或论证依赖时，固定使用 `### 5. 贡献全景与方法总览`。本节先说明首要贡献与辅助贡献的关系，再给出完整执行链或论证链；从 `### 6.` 开始至少展开首要机制，紧密耦合阶段可以合并成节。省略只用于包裹内容的“核心贡献与方法逻辑”标题，结论链条使用方法末节之后的下一个整数。
1. **写全端到端链条**：总览说明起点或初始条件、关键阶段及其顺序、阶段间传递的数据、表示、状态、策略或证明结果、各阶段的局部作用，以及最终输出、训练信号或结论。段落、列表、表格和小型流程图都可以承担总览。
2. **先完成对象消歧**：同一名称对应不同模型、策略、数据版本、状态或层级对象时，在总览中明确各对象的角色、所属阶段和更新关系，后文沿用同一称谓。
3. **按解释需要展开接口与作用**：只有省略后会妨碍复述首要机制、直接证据或成立边界的阶段才单独成节；紧密耦合阶段在同一详细章节说明输入、核心操作、传递对象、输出或训练信号、局部作用、设计理由、直接证据和失败边界。
4. **保持总览与详解一致**：详解覆盖的阶段与总览保持顺序、对象名称和接口关系一致；后文增加关键角色、分支、传递对象或训练信号时同步更新总览。
5. **处理单阶段方法**：方法只有一个实质阶段时，使用 `### 5. 方法总览与完整机制`。首段先说明首要贡献及其与该阶段的关系，再概括输入、核心操作、输出或结论和设计理由；后续段落完成机制、公式、证据与边界解释。
6. **解释公式承担的任务**：关键公式前说明要计算、约束或证明什么，公式后解释变量角色、信号方向、数值或实现后果，以及它怎样连接下一阶段。
7. **证据与边界就近出现**：方法主张绑定原始章节、公式、图表、附录、代码或实现证据；同时说明失败条件、成立边界和会改变结论的未披露项。
8. **按阅读结果验收**：只阅读第 5 节时，读者能够复述首要贡献、完整链条、关键对象及其角色差异，以及最终输出、训练信号或论证结论；读完必要详解后，读者能够进一步复述首要机制的接口、信号方向、设计理由、直接证据和成立边界。来源只给概览时保留最强局部解释，并明确缺失的数据规模、超参数、训练信号、消融或实现步骤。

存在多项贡献时，先完整解释首要贡献，再说明辅助贡献如何支撑它。方法细节不得只停留在模块名称、阶段列表或 Theme 式关键词；表格和流程图承担导航作用，正文继续解释阶段间的数据、状态、策略或证明依赖。

抽象机制在有助于理解时加入一个最小具体例子。例子中的对象、操作与结果应能逐项映射回原始定义，并在例子后回到正式机制；例子用于澄清推理，不替代公式、算法定义和直接证据。

本契约中的“方法”统称材料的可复述工作链。算法论文使用执行流程，系统材料使用数据与控制路径，理论材料使用论证链，综述使用分析框架，模型报告和框架文档使用训练、部署或行为链。

`internal/paper-workflow-method-overview-baseline.json` 记录新契约启用时尚未迁移的 v2.1 笔记及其 `Updated-At`。验证器固定初始 `slug`—`Updated-At` 上限，活动记录只能随迁移缩减。基线时间保持不变时，方法总览缺口作为迁移提示（advisory）；存量笔记发生实质更新时移除对应记录并完成迁移，时间戳变化但仍缺少合格总览会触发错误（error）。新增笔记不进入该基线。

### 关键实验/定理

章节名可以按材料改为 `关键实验结果`、`主要实验结果`、`关键定理`、`文献扫描结果` 或 `方法论论证`。每个核心结果至少包含：

- `证据定位`
- `支持的最窄结论`

`experiment` 模块同时记录对照是否可比。其它模块按 `internal/paper-analysis-modules.md` 选择相应字段。

核心归档通常保留一至三个直接支撑或限制一句话结论的结果。只有省略会改变结论真值、丢失独立证据类型或破坏成立边界时增加结果；同一证据在方法、结果、启发和局限中只保留一个主要展开位置。

### 局限

覆盖首要贡献的成立条件、主要混杂因素、未披露信息、外部有效性和待复验指标。

### 跨论文关系

记录规范来源和本地已有档案直接支持、且会改变理解的主题、引用、方法复用和系统层级关系。普通关系只写新论文；旧论文仅在新证据纠正事实错误、改变一句话结论真值，或用户明确要求跨论文维护时回写。当前没有可靠关系时写明 `暂无高置信跨论文关系。`。

## 条件章节

以下章节只在有实际内容时加入：

- `OpenReview / 审稿意见吸收`：`Review status` 为 `official-review` 时必需；核心归档紧凑记录 decision 或 meta-review、直接影响核心结论的质疑、作者回应和可信度变化，无需逐条复述 reviewer。
- `主要启发`：材料或后续交流产生会改变问题理解、系统设计或诊断方式的稳定认识更新时加入。
- `阅读目标与判断边界`：复杂材料需要先限定范围时加入，也可以把内容并入 `论文脉络` 与 `局限`。

`Reference Intake Brief` 已退出 v2.1。用户指定材料即确定归档对象，笔记不再记录 `merge`、`skip` 或其它准入决策。

`本地讨论补充` 同样退出 v2.1 的正式结构。后续交流按陈述功能直接回流到当前笔记；旧笔记达到事实纠错、一句话结论真值变化或用户明确维护这三类回写条件时，再迁移存量章节并去重，不做一次性批量改写。

### 主要启发构建流程

`主要启发` 记录材料带来的稳定认识更新。它回答三个问题：原有判断在哪些条件下不够准确，材料通过什么机制改变了该判断，以及新判断可以怎样迁移和验证。候选通过下述筛选时，`archive-core` 至多保留一条与首要贡献对齐的首要启发；没有独立认识更新时省略本节。辅助启发只在用户明确要求时增加；v2.1 格式继续接受历史笔记和增强任务中证据充分的多条启发。

#### 内部构建

每条候选启发先完成以下推理链；这些字段用于分析，不作为固定字段写入公开笔记：

1. **原有判断**：记录阅读前采用的设计判断、理论假设、解释方式或诊断方式，并定位到既有文献、领域实践、材料明确讨论的基线、已有归档判断或用户明确提出的认识。无法定位来源时，使用“补充设计变量”“建立局部经验关系”或“增加适用边界”等较弱表述。
2. **认识触发点**：定位材料中的矛盾、异常、反例或关键结果，说明原有判断无法覆盖的具体部分。
3. **关键转换**：识别作者改变的假设、表示、观察对象、优化目标、约束、变量关系或操作方式，并说明哪些性质得到保留，哪些原本绑定的选择被拆开。
4. **作用机制**：解释关键转换如何产生观察结果。机制来自作者解释时保留作者归因；由本地分析推出时明确标注为本地重构。
5. **区分性证据**：找到能够区分当前机制与更简单替代解释的最小对照、消融、反例、定理条件或实现测量。证据只支持相关性时，将机制保留为待验证解释。
6. **新判断**：用一句话写出材料成立后应当如何重新设计、解释或诊断问题。
7. **抽象关系**：把新判断改写为“在条件 C 下，操作或变换 T 通过机制 M 改变结果 Y”。移除论文专有名称时保留实际因果或逻辑结构。
8. **迁移检查**：在目标任务或系统中重新确定 C、T、M 和 Y，并提出迁移成立时应出现的结果以及能够否定迁移的观察。只有产生可证伪预测的对应关系进入正文；表面相似只记录为待验证方向。
9. **来源与边界**：说明论文事实、作者解释、用户判断、本地分析和待验证外推分别承担哪部分结论，并写明成立条件、失效情形和替代解释。

#### 候选筛选

候选启发需要同时具备可归因的认识变化、论文专属的区分性证据、连接证据与新判断的机制、带条件的抽象关系、迁移后的可证伪预测，以及会改变判断真值的失效边界。

以下内容不进入 `主要启发`：方法摘要、结果复述、通用实验建议、评测要求、未披露项、复验清单、没有区分性证据的机制猜测、没有新预测的宽泛类比、为了突出论文而虚构的既有观点、对首要贡献的抽象词改写，以及没有形成新设计或诊断判断的局限。它们分别归入 `论文脉络`、`关键实验/定理`、`局限`、代码与复现或 `跨论文关系`。

#### 公开写法

每条使用 `### N. <可独立成立的新判断>` 命名，并写成二至三个自然段。第一段交代认识触发点、论文专属证据、关键转换和作用机制；第二段给出抽象后的判断，并说明它如何在其它对象中重新实例化以及会产生什么新预测；第三段仅在需要时说明成立条件、失败情形、替代解释和来源边界。标题直接陈述新判断，不使用“需要关注”“值得思考”“进一步验证”等流程性表达。

新契约自 2026-08-05 10:40 起适用于新建或实质更新的 v2.1 笔记。自动检查只验证编号标题、自然段和直接证据定位；认识变化、机制、迁移预测、来源归因与失效边界继续由人工语义门禁判断。更早的存量笔记达到旧笔记回写条件时迁移，不执行一次性全库重写。

## 分析模块

`Material type` 描述材料身份，`Analysis modules` 描述需要执行的分析检查。模块可以组合：

| 模块 | 主要检查 |
| --- | --- |
| `experiment` | 设置、数据、指标、统计、baseline 强度、compute 与实现可比性 |
| `system` | 硬件与软件条件、数据路径、吞吐与延迟定义、资源和成本归因 |
| `theory` | 定义、假设、定理、证明依赖、适用域、反例与系统映射 |
| `model-report` | 数据、训练阶段、硬件、并行、框架、评测、安全和未披露项 |
| `survey` | 纳入范围、时间边界、分类轴、覆盖缺口、引用偏差与时效性 |
| `safety` | 威胁模型、攻击者能力、评测环境、现实迁移性、防御与披露边界 |
| `docs` | 框架文档、明确的实现或版本复核，以及会改变结论的文档—论文冲突；变更历史只在版本差异影响结论时检查 |

模块细则、字段建议和 canary 阶段 advisory 见 `internal/paper-analysis-modules.md`。

## 证据与语义门禁

笔记区分三类陈述：

1. **论文事实**：正文、附录、图表、代码或项目材料直接给出的设计、数字、定理与限制。
2. **作者主张**：作者对贡献、原因、适用范围和意义的解释。
3. **本地分析**：机制重建、因果解释、跨论文比较、工程判断和可信度校准。

关键判断优先定位到原始章节、公式、图、表、附录、页码、代码路径、符号名、tag、commit 或具体 URL。机制分析涉及效率或数学变换时，写清朴素路径、优化路径、成立条件、原始障碍和实现边界。

提交前执行一次合并科学审计，并在同一轮完成以下五项核验：

1. 一句话结论、索引核心信号和正文最深入部分是否对齐同一首要贡献。
2. 只阅读第 5 节时，读者能否区分首要贡献与辅助贡献，复述完整链条、关键对象及其角色差异和最终输出、训练信号或论证结论；读完必要详解后，能否进一步复述首要机制的输入与传递对象、核心操作、设计理由和失败边界，并确认总览与详解的顺序、对象名称和接口关系一致；关键公式是否交代用途、变量角色、信号方向与实现后果；抽象机制是否在需要时得到可与原定义对应的具体例子。
3. 关键结论是否绑定最直接的证据位置。
4. 结论范围是否收缩到证据实际覆盖的边界。
5. 局限是否覆盖首要贡献的成立条件和主要混杂因素。

这五项依赖阅读判断，自动结构检查只承担辅助作用。审计发现问题时只回到受影响的证据、结论或章节；修订后复查对应项，无需重新运行整套阅读流程。

存在 `主要启发` 时，人工门禁逐条核验：标题是否陈述新的设计、解释或诊断判断；原有判断是否可归因；论文专属证据是否触发了认识变化；区分性证据能否支持机制并排除更简单的解释；抽象后是否保留条件、变换、机制和结果之间的关系；迁移是否产生可证伪预测；失效边界是否会改变判断真值；内容是否实际属于方法、结果、局限或复验清单。此项保持人工检查；关键词或固定字段无法替代语义判断。

### 术语可读性（写作建议）

英文术语、缩写或指标首次出现在解释性正文时，优先补充简短中文括注，例如 `tie（平局）`、`SNR（信噪比）`。中文直译仍不足以说明含义或计算口径时，再用一句话单独解释，例如说明 `pairwise accuracy（成对准确率）` 如何判断一对样本并统计正确比例。标题、`Source` 字段和代码标识符无需重复解释。这项建议由提交前人工阅读检查，不设置自动术语扫描。

## 公开审稿核验

每篇材料都在 `Source -> Review status` 记录 venue 与公开审稿状态。`analysis-only` 只采用规范来源明确显示的状态。`archive-core` 优先使用来源中的审稿 URL；来源没有审稿链接时，最多执行一次标题或 arXiv id 匹配，未找到即记录 `not-found`。

`official-review` 增加紧凑章节，优先记录 decision 或 meta-review、直接影响一句话结论的质疑、其中披露的作者回应和可信度变化。decision 或 meta-review 没有披露作者回应时写明“未在 decision / meta-review 中披露”，无需为补齐字段读取 rebuttal。只有用户明确要求、审稿意见相互冲突，或回应会改变核心结论时，才展开 individual review 与 rebuttal。其它页面类型只记录页面直接支持的状态；社区传播、工程采用、proceedings 状态和正式审稿认可分别表达。

## 作者核验与关系所有权

`archive-core` 从论文作者块保留全部可解析作者、作者顺序、论文时机构和明确的共同一作或通讯作者标记，并检查本地重名、作者重叠与已有 profile。团队署名和无法可靠拆分的超大作者列表按团队处理。身份仍有歧义时保留论文级信息和歧义说明，不要求外部检索或新建 profile。

以下任一条件触发 `enrichment` 作者核验：用户明确要求作者、机构或账号分析；身份冲突会影响论文归因或现有链接；作者关系本身是核心结论或用户明确要求的跨论文关系。增强范围先绑定到“指定作者 × 指定字段”。只有用户要求完整作者关系或 profile 完善时，才扩展到作者顺序前两位、论文明确标注的共同一作和明确通讯作者；普通作者只复用已有 profile，用户明确指定时可以例外新建。

`enrichment` 使用主页、机构页、GitHub、Hugging Face、ORCID、Scholar、DBLP、OpenReview 与 X 核验指定字段；X 只在已有强候选时核验。请求包含代表论文或 profile 完善时，才将已核验个人主页明确选择或重点展示的论文写入 `representativePapers`。完整时间顺序发表列表不自动视为代表性论文。检索过程与未采纳的信息只保留在临时记录中。

## 交流沉淀与版本更新

用户后续提出的概念修正、反例、公式化重述、工程判断、可信度调整和跨论文联系，优先写入当前新笔记。旧笔记只在新证据纠正事实错误、改变其一句话结论真值，或用户明确要求维护时回写：方法定义与推导进入 `论文脉络`，实验解读与证据定位进入 `关键实验/定理`，反例、未披露项和复验条件进入 `局限`，跨材料判断进入 `跨论文关系`，会改变理解且具有迁移价值的综合判断进入 `主要启发`。同一判断只保留一个主要归档位置，相关章节使用短引用建立联系。

来源出现新版本时，比较元数据、方法定义、实验数字、图表、作者、机构、审稿状态和限制。实质变化更新 `Updated-At`；链接与排版等维护修改保留原时间。

## 论文删除与反向清理

删除论文前遵守项目高危操作确认规则，明确绝对路径、操作类型和数据丢失风险并取得用户二次确认。确认后同步处理论文文件、索引行、标签分配、失效关系、静态图片和作者 profile。
